What it is

A channels MCP that hands your agent text.

Two faces. As a server: any tokened agent can send messages and notifications with delivery receipts. As a client: every inbound message is forwarded, sender-tagged, as a standard MCP tool call — with zero routing intelligence.

Phylax transports. Ring routes. Zenod remembers.
Key positioning points

Why Phylax, in five lines

  • Channels in one place. WhatsApp and Telegram credentials, settings, and pairing live here — not scattered across agents.
  • Transcription at the edge. Voice notes become text before they leave Phylax; cost rides the payload; a media file is never transcribed twice.
  • Never a silent ack. Every send returns a delivery receipt or fails loudly.
  • Zero routing intelligence. Inbound goes to exactly one configured downstream — the Ring by default, any agent you choose.
  • Standalone-sellable. The "wire me to any agent" panel makes Phylax a notification MCP in its own right.
The multi-tenant config

One container per phone number.
Users are rows.

The honest exception

Every other unit is one container for all tenants. Phylax is keyed to the physical resource — the phone number it operates. Senders and users are whitelist and pairing rows, never a deploy.

Breakage contained

Channel libraries are flaky and ToS-exposed. When a channel breaks, it breaks inside Phylax — the Ring and your units never feel it.

Zero-restart onboarding

New users are rows written through a runtime config API. No redeploys, no downtime.

In the suite

The edge of the Council.

1

A WhatsApp voice note arrives. Phylax transcribes it at the edge and forwards sender, transcript, artifact ref, and usage — one standard MCP call.

2

Ring maps sender to tenant and routes; Zenod files with provenance — no double transcription, by construction.

3

The reply comes back through Phylax — one voice, deduped, with the receipt trail.

Boundaries

What Phylax owns — and refuses.

  • Owns: channel credentials and settings, edge transcription, delivery receipts, the interrupt privilege.
  • Never: routes (Ring), remembers (Zenod), posts outbound content (Callisthenes), executes (Epaminon).
  • If transcription fails, the message still forwards immediately, flagged — the conversation never queues behind a model.
Surface

Three tools, two faces.

Agents send through the server face with your token. Your inbound flows out the client face to the one downstream you configured. The tenant UI handles pairing, Telegram bot setup, and channel settings.
