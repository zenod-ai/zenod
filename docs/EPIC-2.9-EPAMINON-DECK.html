Public surface

The main tool is prompt-first, not ticket-first.

Public MCP allowed

`run_task`Text prompt, effort, repo/path, output target, MCP context, skills.
`execution_status`State, elapsed, phase, evidence, transcript, blockers.
`run_existing_issue`Compatibility path for explicit GitHub work issues.

Suite lane private

`enqueue_execution`Archus to Epaminon only, not the public UX.
`approve_execution`Suite approval leg for irreversible outcomes.
`apply_execution_event`Epaminon to Archus fact reporting.

Worker profile configured

InstructionsGeneral worker policy and project-specific guidance.
MCP serversMemory, outbound, repo, or custom servers prewired into the run.
SkillsNamed behavior packs available to the harness.
Execution path

The main flow should be orderly and inspectable.

acceptedMCP call returns an execution id immediately.
queuedConcurrency and worker profile are resolved.
runningHarness starts with effort level and prewired MCP.
artifactResult lands in repo, PR, file, issue, or artifact store.
reviewIrreversible outcomes wait for approval.
doneStatus, evidence, transcript, and receipt persist.

GitHub issues are useful receipts and targets, but they are not the prerequisite UX for every run.
