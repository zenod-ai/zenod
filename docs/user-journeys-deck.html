Strategy

The product proves itself by selling itself

Zenod's own X + Reddit presence is run by Zenod. Every post is a live demo; the growth chart is the sales page; the TrustMRR listing is the testimonial. Customer #0 is us — every journey below ships for us first, then gets a login screen.

Why this works

The category's winners already proved it: Postiz grew on build-in-public, open source as marketing. Zenod goes one further — the marketing is literally the product executing. Nobody can fake that, and nobody can copy it without having the product.

What it forces

Dogfooding forces the exact journeys a customer needs: feed memory, build backlog, queue posts, review on a board, feedback loops in. If a journey is too clunky for us, it's not ready to sell.

What we already have

The engine exists: librarian + vault (memory), backlog service on GitHub issues, X/Reddit MCPs (post_tweet, post_reddit, read_x_mentions), and the Council roster. T0 is wiring, not research.

Scope discipline

What T0 is not

In — the loop, minimal

Memory → backlog → throttled queue → X/Reddit publish → board feedback → memory. One tenant (us). Config by file/settings UI is fine. Board can be plain — GitHub issues + a thin view is acceptable if feedback flows into memory.

Out — everything ambient

No WhatsApp/Telegram, no multi-tenant, no OAuth flows, no Composio, no thinking sessions, no proactive proposals. These are T1–T3 for a reason: each one is only credible after the loop demonstrably works in public.

The T0 demo that sells

A stranger opens Zenod's X profile: daily posts, real replies in threads, visible improvement week over week. Then reads the pinned post: "this account is run by the product." That single artifact is the launch.

The T0 risk to watch

Quality, not volume. One AI-slop post in a Reddit thread costs more than ten good posts earn. Phylax's gates and low N are features — start N=1/hour, earn the throttle up.
