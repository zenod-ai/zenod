What it is

A librarian your agents report to.

Every agent you run reads your context; only Zenod may write it. Writes are gatekept, reads stay open, and every mutation commits to your repo with a receipt.

Server-enforced librarianship, git provenance, and agent-mode answers.
Key positioning points

Why Zenod, in five lines

  • You own the vault. A wiki-style GitHub repo of plain markdown — Obsidian-compatible, portable, yours forever.
  • One writer. Zenod is the only agent allowed to write memory. No silent edits, no drift.
  • Git provenance. Every stored memory is a commit. Evidence, not vibes.
  • Agent-mode answers. ask_brain reasons over the vault, not just retrieves from it.
  • MCP-native. Connect Claude, Codex, or any MCP client with one URL from the dashboard.
The multi-tenant config

One container, all wiki brains.

A customer is a row

One always-on Zenod container serves every tenant. A new customer is a tenant row, never a deploy. Landing, sign-in, billing, dashboard, and MCP endpoint all live in this one container.

Isolated by construction

Every read and write is tenant-scoped: per-tenant vault clone, per-tenant databases, encrypted key custody. Your token is your tenancy.

Self-host = same image

The identical container with a tenant count of one, UI included. Free forever, AGPL-3.0. Hosted is the same engine, managed.

In the suite

The memory is the center.

1

A voice note hits Phylax, which transcribes at the edge and forwards it, sender-tagged.

2

Ring maps sender to tenant and files it through Zenod ingest — transcript provenance recorded, never transcribed twice.

3

Zenod commits it to your vault and returns a receipt; the receipt drives every follow-up.

4

Any agent — yours or a governor's — answers from the same owned memory.

Boundaries

What Zenod owns — and refuses.

  • Owns: the vault, ingest & digest, file archive, memory receipts.
  • Never: sends outbound (Callisthenes), routes channels (Ring), transports messages or transcribes at the edge (Phylax), executes jobs (Epaminon).
  • Humans sign in with GitHub; tokens are agent credentials only, shown inside the dashboard — never a public login.
