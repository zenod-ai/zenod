## Why the 1 h stall alert (A8) did not fire

The A8 rules are: row 3 red when saves fail for over an hour with none finished, and row 4 red when a WhatsApp message gets no reply for an hour.

1. **The probe read only the running zenod-mt container.** Production rolled about every 20 min, so the "saves failing since" clock restarted at each roll and never reached an hour.
2. **The probe read only `docker logs` stdout.** Zenod logs failed jobs with `console.error`, which `docker logs` sends to its stderr, so the probe never saw a failure line. The A8 save rule could never have fired. The A8 proof on 2026-11-06 came from the reply rule.
3. Row 4's rule could not help either. No WhatsApp message arrived between the 16:14 "Saved" and 18:50, and the 18:50 message was a question that never gets a "Saved". At 19:50 the rule turned row 4 red anyway, and that red would have stayed until his next voice note.

Fixes, all in `docs/health/s1-live` (main-direct; installed in `~/.local/lib/epic6-s1-health` on VPS3):

- `7622c9c`: `log_spans` reads every container Docker keeps for the service (the swarm keeps the last 5), both streams, in time order. Covered by `test_probe.py` (3 tests). A dry run at 19:49Z turned row 3 red: "saves failing since 18:32:40 UTC (76 min ago)". That is the oldest log Docker still kept. The true start was 16:14Z.
- `144f7e5`: a chat job that finishes within 5 min of a WhatsApp message counts as its reply. Covered by `test_aggregate.py` (35 tests).
