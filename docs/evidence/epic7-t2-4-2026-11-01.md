## Step 2: what a phone link needs (read-only)

Code path (also mapped in [T1 step 4](epic7-t1-new-user-path-2026-10-31.md)):

1. A signed-in hosted customer opens Channels and enters their WhatsApp number. The console calls `POST /api/channels/whatsapp/challenge`. Phylax then (`hostedChannels.ts` ~985–1030):
   - refuses with `already_connected` if the tenant already has a verified phone;
   - refuses with `assertPhoneAvailable` if **the number is verified on another tenant** ("That sender is already connected to another Zenod account.", 409);
   - otherwise registers the phone with a one-time code.
2. The user sends that code **from that phone** to the Zenod number. `verifyInboundReceipt` (`phylaxTenantSettings.ts` ~1195) marks the phone verified. After that, messages from that sender go to the tenant's Zenod `/mcp`.

So the proof needs a human-held WhatsApp sender and a signed-in console session for the tenant. A Telegram binding would not prove the WhatsApp path that E7-3 needs.
