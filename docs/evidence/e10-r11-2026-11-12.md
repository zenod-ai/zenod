## Why the T7 account and not a new empty one

The brief allowed the T7 account only if the health check needs just `tools/list`. Glama's check runs `initialize` and `tools/list` and indexes the tool schemas (its TDQS is scored from those schemas, no tool is called), so no AI allowance is used. A new empty Zenod account was not possible without Jordi: production sign-up is Google (closed to new Google users except the allowlist) or GitHub; the team has no agent-owned GitHub account, and scripting a new GitHub or Google account breaks their rules and needs a phone. The production control-plane key that could make a bare tenant is per-app and refused to agents by design (`secret run` refusal), so it was not used.

Risk and rollback: Glama holds a bearer token for the T7 test account, which holds only rehearsal notes. Revoke it at cloud.zenod.dev → Settings → Connect AI apps (token "Glama health check (tools/list only)"), or Admin → Test profile → Delete on Glama; the check then fails again. The DNS record can be removed in Cloudflare (`_glama-claim.zenod.dev`), which unclaims the listing.
