## Defect fixed: cloud row falsely amber (2026-11-03, run_8f6d7ad7)

Seen 20:30:20Z: `cloud` amber, "live sha 58563d9 is behind the newest published image 779f74c for over 30 min".
`779f74c` is the 2026-09-07 publish of #1230. Cause: `probe.py` asked `gh run list --workflow publish.yml
--status success -L 1` and trusted the API's order; a 1-run page sometimes comes back with an old run (the 20:25Z
probe got `58563d9`, the 20:30Z one `779f74c`). Fix: read 20 runs and pick the newest by `createdAt`
(`aggregate.newest_publish()`), tests `NewestPublish` (32 tests pass). Installed to
`~/.local/lib/epic6-s1-health/` on VPS3; probe at 20:33:47Z: cloud green, "sha 58563d9 (matches last publish
58563d9)", `raw.publish.headSha` 58563d9, and the VPS1 copy behind health.zenod.dev reads the same. The false
amber stays in the cloud row's kept last error (20:30:20Z) as a truthful record of what the probe saw; the next
real cloud error replaces it.
