## What shipped

- **Sweep** (`packages/core/src/engine/treeSweep.ts`, engine `sweepTree`). It keeps a tree vault tidy and decides nothing for the person:
  - Stale working roots (no capture in 30 days, ops rollups excluded) get one proposal line each. Nothing is moved.
  - Leftover `Inbox/filing-…` / `Inbox/needs-filing-…` receipts are handled when they are at least 2 days old and no filing job is still queued for them. Each is re-filed with E9-2b's placement, then moved byte for byte to `Archive/Inbox/`.
  - Duplicate titles get one merge proposal line. Nothing is merged.
  - Proposals go to one vault page, `Inbox/Tree sweep.md`, written only when there is something to propose.
- **Safety (E9-A2).** A guard refuses three things: any write under `Log/` or `_attachments/`, any removal without an identical copy under `Archive/Inbox/`, and any rise in tree lint errors. All of a sweep's changes go into ONE vault commit, so `git revert` undoes the whole sweep. On any failure the working tree is reverted and nothing is committed.
- **Scheduling.** A `tree_sweep` job runs on the tenant's serial durable task lane (the same lane as filings) and on the engine's background write lane under the vault write lock, so it never runs alongside a live filing. A per-runtime clock queues it at the first check inside the 02:00–06:00 UTC window from Sunday 02:00 UTC. The key `tree-sweep:week:<Sunday>` gives one run per week, even across restarts. The sweep makes no model call.
- **Surfaces.** `GET /api/memory/sweep` returns the schedule, the next run and the last run's counts. `POST /api/memory/sweep/run` runs a sweep now. `GET /api/console/memory-sweep` adds a one-line suggestion for the console Memory tab (E9-2e).
