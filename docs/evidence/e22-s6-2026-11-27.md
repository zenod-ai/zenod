## The change (zenod PR #1777, merged 2dbbdaf6, `packages/core/src/engine/treePlacement.ts`, `engine.ts`)

- ✓ Cause 1: a rescued point with no subject page of its own grows the closest page the same note already reached (`notePages`, `notePageChoice`). A point the organiser gave its own subject keeps it, so a note that really covers two topics still grows both.
- ✓ Cause 2: a leaf this note made counts as one of its pages: at most one new page per note, the other points join it.
- ✓ Cause 3: with no page and a weak word score, the classifier picks among the root topics first (`pickRootTopic`). Each root is described by its confirmed subtopics, then leaves spread over the branch, because root summaries are often only counts. The pick also sees the whole note and the app it was recorded in. Only a pick of a listed root at confidence 0.5 or higher counts (`ROOT_PICK_MIN_CONFIDENCE`, or the vault threshold if lower). claude-haiku-5-5 gave the right roots 0.45 to 0.6, so the usual 0.7 placed nothing. A cut-off fragment is a one-off (`isOneOff`), and `Source app:` is an ingest line.
- ✓ The repair paths (`noteLinker`, `treeSweep`) use the note's pages the same way.
- Tests: `packages/core/test/e22s6FilerMisses.test.ts` (11, shaped on alpha9's Log ids in made-up words: the repo is public), `landingRescue` updated.
