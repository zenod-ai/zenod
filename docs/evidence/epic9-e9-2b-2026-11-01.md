How each audit §5 rule is applied:

- **Rule 1.** The Log append is unchanged.
- **Rules 2–4 (vaults with `Tree.md` only).**
  - A touched page with no resolvable lineage gets `parent:` set to the best node. Matching is token overlap with node names (×2) and summaries.
  - A deeper page wins only when its own name matches. Provisional pages never adopt others.
  - A weak match also sets `provisional: true`.
  - A capture that reached no page becomes a provisional `Notes/` leaf under the closest node.
- **Rule 5 (vaults with `Tree.md` only).** An agent ops report becomes one dated line in the project node's `## Ops rollup` section, e.g. `- 2026-11-01 ops (2): [[…^e-a]], [[…^e-b]]`. The node's `updated:` is untouched.
- **Rule 6 (every vault).** The Log entry gets `- filed: [[page]] (Working › Node › Page)`, with `· provisional` or `· ops rollup` when they apply. When nothing was worth a page it gets `- filed: log only (reason)`.
  - The line is appended, so the Log stays append-only.
  - A non-last entry is addressed as `- filed e-xxxxxx:`, without a caret, so anchors stay unique.
  - Each page is recorded once per entry. Pending (retryable) filings write nothing until they settle.
  - A tree-less vault gets `- filed: [[page]]` with no path.
- **Lint.** The touched pages must pass `lintTree()` and `zenod lint`. Otherwise the placement is undone and only a plain `filed:` line is written. The filing itself never fails because of placement.
