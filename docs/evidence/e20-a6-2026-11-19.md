# EPIC-20 A6: delivered or read, not only sent (notify_receipt), 19 Nov 2026

Objective: Zenod: 5 testers: the team (and alpha9's briefing watcher) can now tell that a WhatsApp message reached Jordi's phone, not only that Phylax sent it.

```
 console ── notify ──► Phylax ──► WhatsApp ──► Jordi's phone
                        │                         │
                        │  ◄── receipt: delivered (3) / read (4,5) / error (0)
                        ▼
           outbound intent row: delivery_status, delivery_status_at   (forward only: read never goes back)
                        ▲
 console ── notify_receipt {sentMessageId} ──► {sentMessageId, channel, status, at}   (own messages only, no text)
```

## 1. What was missing

alpha9 asked (E42-S137) for the delivered/read state "Phylax already stores". It did not: no code listened to WhatsApp's `messages.update` receipts, and `outbound_status` only ever held `sent`. So A6 adds the listener first, then the tool.

## 2. Change ([#1708](https://github.com/zenod-ai/zenod/pull/1708), merged `c4c920c`)

| part | what |
|---|---|
| `whatsappGateway.ts` | listens to `messages.update` for messages we sent: 3 delivered, 4/5 read, 0 failed (2 = server ack stays `sent`); logs `[whatsapp] receipt <id> <status>` (no text) |
| `whatsappStore.ts` | two additive columns on `whatsapp_outbound_intents` (`delivery_status`, `delivery_status_at`); forward-only update; tenant-scoped reader |
| `phylaxChannels.ts`, `phylaxUnit.ts` | read-only MCP tool `notify_receipt`, in the notify profile (`phylax-notify-v1`) beside `notify` and `channel_status` |

Tool contract:

- input `{ "sentMessageId": "3EB0…" }` (the bare id from the notify receipt; `whatsapp:<id>:sent` is accepted too, `…:sent picture` is not, pass the bare id)
- output `{ "sentMessageId", "channel": "whatsapp", "status": "pending|sent|delivered|read|failed|unknown", "at": ISO or null }`
- same token as `notify`; an id another account sent reads `unknown`; no message text is ever returned.
