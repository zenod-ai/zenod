## Causes

| symptom | cause | fix |
|---|---|---|
| two final rounds (answers 1, 3) | Since T7-F10 every round offers every tool, and Sonnet 5.5 gets `tool_choice: auto` (a forced choice is a 400 with thinking). The model cannot tell that a round the **token budget** made final is the last one. It read, got "not available in this round", and submitted in the next round, which was final as well. | The final round gets a `FINAL ROUND: … call submit_memory_answer now` note as its last message. Nothing earlier changes, so no thinking signature or cache prefix moves. The refusal stays as the fallback. |
| 25 s after the last round | `finalize` re-checks every selected source with a read. On a Drive vault each read probes the published revision: it downloads the manifest and the **whole Git bundle**, then `git bundle verify` and a cold clone. The re-checks ran one after another, so the gap grew with the number of sources (1 → 8.6 s, 2 → 14 s, 3 to 4 → 25 s). | The re-checks run together and share one probe. A bundle whose Drive md5 is unchanged since it was verified for this manifest is not downloaded or cloned again. |
| read rounds about 10 s, round 1 at 34.8 s | The same probe runs in every `read_note`, and in the search's single-hit read in round 1. Answer 1's round 1 was also the first model call after the restart (`cache_read=0`, so the 9K-token prompt was not cached yet) and the first probe after the promote. | The same bundle cache. Each `[answer-round]` line now adds `round_ms` and `tool_ms`, so the live check measures how much of a round was tools and how much was the model. |
