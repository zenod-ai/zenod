## How it works

- **Gate** ([gate.py](../health/s1-live/gate.py), Dokploy app `zenod-health`, redeployed 2026-11-03T14:47Z):
  `GET /login/<64 hex>` hashes the token and atomically renames `/srv/magic/<sha256>` to `.used`, then checks the
  expiry stored in the file. Valid → 303 to `/` with the usual signed 30-day cookie. Used, expired or unknown → 401
  with the sign-in form and "This sign-in link was already used or has expired." A browser that is already signed in is
  just redirected to `/`. The rename makes the link single-use under concurrent clicks and across container restarts.
  Request logs print `/login/<link>` in place of the token.
- **Minting** ([probe.py](../health/s1-live/probe.py) `signin_link`, the existing VPS3 timer, every 5 min): keeps one
  unused link. A new one is minted when the last was used or is within a day of its 7-day expiry. The token is
  written only to `~/.config/zenod-health/signin.json` on VPS3 (0600) and the tailnet page. VPS1
  `~/.local/share/zenod-health/magic/` (0700, mounted at `/srv/magic`) holds only hashes and expiries. `.used` files
  are pruned after 30 days.
- **Exposure**: the link appears only on pages that already show the same data without a password, the tailnet page
  and the signed-in copy. On health.zenod.dev a script removes the box. Anyone who can open the tailnet page could
  already read everything health.zenod.dev shows, so no new access is granted. Nothing secret is in the repo.
