Agents cannot read the cause, because `sudo docker logs` was removed from the VPS1 sudo list (only `docker ps` and `stats` remain).

## Findings

- **F1. A new user's Google Drive vault does not come up on production (blocks testers).** Setup writes the folder and first files, then fails its own durability check. Recovery and reconnect both fail. Every tester without GitHub picks Drive, so none of them could save anything. Production readiness has carried `google_drive_vault_acceptance: false` (advisory) since the Drive vault shipped. As far as the evidence goes, no Drive vault has worked for a real production user (Jordi's own account uses GitHub). Cause unknown, because agents can no longer read `zenod-mt` logs. **Needs a fix row** with production log access (see the ask-tier below). The account stays as it is, so the fix can be tested on it: operations@alpha9.io, Zenod user `usr_b17aca05…`, free pass to 2026-12-11.
- **F2. tester-watch still cannot see this account (round 3 F2 confirmed).** At 05:44:57Z, `tester-watch --redact` lists only the old T4 code `t7…` ("not signed up"). The new €0 subscriber is in no table the team watches. The only places it shows are Stripe (Jordi) and `cloud.zenod.dev/admin/testers` (admin only). The fix is the same as round 3: tester-watch reads the tester-flow testers through a narrow read rule.
- **F3. Stripe checkout opens in USD from a US IP.** Adaptive pricing showed $10.45 (4% conversion fee) until EUR was picked. For testers in Europe it will show euros, so this is low priority. It is worth knowing when reading screenshots.
- **F4. The Stripe product text says "one GitHub-backed vault",** while the app says GitHub is not needed and offers Drive first. It is a one-line copy fix in the Stripe product description.
- **F5. No login for Bitwarden.** The account signs in with Google and has no Zenod password (root L-53 does not apply). The billing address entered at checkout is a placeholder (Carrer de Prova 1, Barcelona).
- Housekeeping: a leftover `x11vnc` from round 3 (localhost :5979, display gone) was stopped. Xvfb and Chromium for this round were stopped at the end. The `operations-profile` and its Google session stay.
