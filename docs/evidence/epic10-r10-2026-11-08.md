## Findings

1. **Official MCP Registry** is the only live listing that search can find. Search matches only the server name and sorts A–Z, so Zenod's first registry name (retired 2026-11-12, now `io.github.zenod-ai/zenod`) is 62nd of 323 for "memory" and never matches "whatsapp", "notes" or "second brain". The UI loads 96 at once, so Zenod is on the first page, below the fold. Copy cannot fix this. Only the name counts, and the domain namespace is fixed by the DNS proof.
2. **Glama marks Zenod Unhealthy**: "The last two health checks of this connector failed … add or update a test profile under Admin → Test Profile." Glama hides Zenod from its connector search, even for the query "zenod". Copy is not the cause. The health check cannot sign in because Zenod's MCP needs OAuth. Fix: claim the listing (GitHub `zenod-ai`) and add a test profile with a dedicated test Zenod account. That creates a new credential held by a third party, so it is ask-tier (below).
3. **"whatsapp memory" is empty** on mcp.so, the Gemini gallery and the Registry, and on Glama it only returns generic memory and WhatsApp-messaging servers. No competitor owns the phrase. Once Zenod is indexed, a listing whose name or first sentence contains both words should take the top spot.
4. **Smithery search returns nothing** for any term since Smithery became part of Arcade (31 Oct). The E10-4 Smithery half cannot be measured or met there right now. Raise it when E10-4 is judged.
5. Not yet indexed: mcp.so (issue 6906 open), Gemini gallery (not crawled yet), MCP Market (not submitted), Anthropic directory (R5, waits on E10-A2), awesome-mcp-servers (PR 18864 open, no search).
