## What was built

- **The live tier** (`scripts/memory-eval/live.mjs`) uses the client production builds for its background route: `createBrainLlm`, provider `deepseek`, model `deepseek-flash`, thinking off. It files the 8 notes Jordi judged and answers his 20 judged questions (`rq01`–`rq20`) on a throwaway copy of his vault. Each answer is also checked for the expected facts in the model's own words.
- **The cache** stores every call under a hash of what was sent. Before hashing, these run-specific parts become placeholders: Log anchors, dates, clock times, weekdays and page revision hashes. They are swapped back on replay.
- **The caps** are $0.25 a run and $3 a month, kept in a ledger. A call is refused before sending when the spend so far plus 1 cent for each call in flight could pass a cap. Refused items count as not run.
- **Nightly**: after the offline runs, off DeepSeek's peak hours, once per production roll or day. The key comes from `secret run DEEPSEEK_API_KEY --from zenod-tests` and stays in memory only. The step is skipped while the key is absent: checked, `app 'zenod-tests' has no stored keys`. The stand-in runs the same slice on the same code, so the dashboard can compare the two.

## Proof without a key

| Check | Result |
|---|---|
| Jordi's slice, first run, stub model behind the live tier at a fake $0.001 a call | 123 calls: 18 classify, 85 compose, 20 answers. $0.123 counted and in the ledger. Ingestion 87.5% (7 of 8), retrieval 90% (18 of 20) |
| Same slice, rerun | **0 calls, 123 from the cache, $0 spent**. Same ingestion, retrieval and error rate |
| Same slice, $0.02 run cap | 10 calls, then 42 refused before sending. Only the 10 questions that ran are scored |
| DeepSeek's API mocked over HTTP (the real client, the real usage pricing) | usage priced from the cache hit/miss split. Rerun: 19 of 19 answers replayed, 0 answer calls sent |
| Unit tests in CI (`live.test.mjs`, 8) | cache replay with a new anchor, a clock time a minute later, run cap, month cap from the ledger, no invented methods |

Bugs found and fixed on the way: the answer prompt carries "now HH:MM UTC", and filing sees page revision hashes. Both changed every run and defeated the cache until they were normalised. A value showing up twice in one run used to shift the placeholder numbering. Placeholders are now numbered per occurrence.

## What waits

- **E15-A7**: a separate DeepSeek test key, stored as `zenod-tests/DEEPSEEK_API_KEY`. `secret run` only serves keys of class `shared`. The secret tool files an unknown name like this one as `per-app`, which `run` refuses. So the key must be stored as class `shared`, or the tool must learn that DeepSeek API keys are shared. Production's own key stays per-app and is never used here.
- **Expected first-run cost**: about $0.10 to $0.20 off-peak for the slice, under the $0.25 run cap. Reruns on unchanged code and vault cost nothing.
- **Answers model**: answers run on DeepSeek too, while production chat answers on OpenRouter. Brief rule: no OpenRouter spend for tests.
