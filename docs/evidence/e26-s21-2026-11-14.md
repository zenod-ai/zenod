## The read

`GET https://cloud.zenod.dev/api/private/testers/applicants` with `Authorization: Bearer $ZENOD_APPLICANTS_READ_TOKEN`. `Cache-Control: no-store`.

```json
{
  "schema": "zenod-applicants/v1",
  "at": "2026-11-14T12:00:00.000Z",
  "steps": ["applied", "accepted", "signed_up", "whatsapp_linked", "first_save"],
  "applicants": [
    {
      "id": "a_3f9c0d1e2b4a5c6d",
      "at": "2026-11-13T20:33:00.000Z",
      "name": "Ana",
      "source": "P-0219",
      "step": "signed_up",
      "status": "accepted",
      "reached": {
        "applied": "2026-11-13T20:33:00.000Z",
        "accepted": "2026-11-13T20:33:05.000Z",
        "signed_up": "2026-11-13T20:36:00.000Z",
        "whatsapp_linked": false,
        "first_save": null
      }
    }
  ],
  "test_applications": 5
}
```

- `id` is stable and opaque (one per person), so the console sends each person once and can send again when `step` moves.
- `name` is what the applicant typed in the new optional "Your first name" field, else the GitHub login they signed in with, else null. Anything that reads as an email or phone number is dropped.
- `source` is the `?s=` post id from the link they came by (kept for the visit) or the referring host. Applications before this change have `source: null`.
- `whatsapp_linked` is read from Phylax for signed-up accounts (cached 5 minutes); null when Phylax does not answer.
- `first_save` is the first finished save in the tenant's tasks, self-tests left out.
