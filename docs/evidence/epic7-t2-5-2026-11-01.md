## What shipped

- The hosted console's overview page now has a **Recent saves** card under the usage card. It shows the signed-in tenant's last 20 captures, newest first. Each row has the time, the channel (WhatsApp voice / text / image, Telegram, AI assistant), a snippet of at most 140 characters, the Saved reply headline the user got back (for example "Saved." or "Saved — filed to Inbox; …") and a link to the note in their vault. Captures still in progress show "Saving…", and failed ones show "Not saved.".
- `GET /api/console/recent-saves` (`packages/server/src/customerLayer.ts`) needs a customer session. It finds the account with `resolveActiveTenantForUser(session.user_id)` and that account's runtime only. Responses: no session 401, no active tenant 404.
- Source: the per-tenant task-job store (`/data/<tenant>/tasks.sqlite`). It already records every capture when it is saved: `store` for WhatsApp text and connector notes, `media_ingest` for voice notes and images, and the follow-up `enrich_memory` filing that the ingest receipt names in `digest.enrichmentJobId`. So nothing new is written, and the page never reads the vault. `TaskJobStore.recentCaptures` filters by `tenant_id` and skips `selftest` rows. The projection is `packages/server/src/recentSaves.ts`.
- What the UI never receives: job error text, prompts, tokens, or non-https links. `store_memory`'s MCP receipt headline now comes from the same `storeReceiptHeadline`, so the console uses the same wording as the reply.
