# E20-A8: a typed WhatsApp "now" reaches EpicTeam

Objective: Zenod: Get 5 testers. Jordi's daily use of the Zenod number is the loop; one typed word has to reach EpicTeam without a voice note.

Ask: alpha9 desk note 2026-11-22 (EpicTeam E46-S106), from Jordi's vn_3a3940c5.

## What changed

```
owner types "Now!" on WhatsApp
   -> Phylax -> tenant chat job (surface whatsapp)
   -> channel brain: is the whole message one subscription's reply word?
        yes -> keep it as a text note, tell that subscription only, send NO reply
        no  -> as before (keep / answer / job)
```

- A subscription declares its words with `reply_words` (list of up to 5 words, each up to 32 characters). Compared on the whole message, lower case, punctuation and spacing ignored: `Now!` and `now` match `now`; `now please` does not.
- Declared on `POST /api/subscribers/v1/subscriptions` (new), `PATCH /api/subscribers/v1/subscriptions/:id` (set or clear on an existing subscription), and in the Subscribers tab API (`POST` and `PATCH /api/subscribers`). Shown as `reply_words` in every subscription JSON. Stored in one new nullable column, `subscriptions.reply_words` (added to older databases on open).
- Only the tenant's verified WhatsApp sender can reach this: the message comes through Phylax's route for that sender, as for every typed WhatsApp message. Telegram, MCP and the web chat never relay.
- A paused subscription, or one without words, never matches: the word is an ordinary message again.

## The event (same type as a voice note, `content_type` text)

POST to the subscription URL, signed exactly as `voice_note.captured` (`x-zenod-signature: t=<unix>,v1=<hmac>`, `x-zenod-event-id`, `x-zenod-event-type: voice_note.captured`, retries 2 s and 10 s):

```json
{
  "id": "evt_...",
  "type": "voice_note.captured",
  "created_at": "2026-11-23T00:10:00.000Z",
  "test": false,
  "subscription_id": "sub_...",
  "note": {
    "id": "Log/2026-11-23.md#^e-...",
    "captured_at": "2026-11-23T00:10:00.000Z",
    "source": "whatsapp",
    "content_type": "text",
    "url": "https://<zenod host>/api/subscribers/v1/notes?id=Log%2F2026-11-23.md%23%5Ee-..."
  }
}
```

Read it with the connection's `zvn_` token: `GET /api/subscribers/v1/notes?id=<note.id>` returns `{ "note": { "id", "text": "Now", "captured_at", "source": "whatsapp", "content_type": "text" } }`. A typed note is readable only when Zenod announced it to that connection; any other typed note answers 404. The safety-net list (`GET .../notes?since=`) stays voice notes only.

Receivers that only handle voice notes should branch on `note.content_type`.

## One answer, not two

The chat job's result is `{ "outcome": "relayed", "text": "", "silent": true }`. Phylax sends no WhatsApp message for it (its existing `suppressReply`), so the only answer is EpicTeam's. A voice note still gets Zenod's own "Saved" receipt as before.

## Side fix

A job queued from inside a running job while its lane was finishing waited for the next 30 s poll; the queue now re-runs the lane. The typed word is kept the moment it arrives.
