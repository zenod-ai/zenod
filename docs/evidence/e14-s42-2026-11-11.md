# E14-S42 evidence: new pages keep their whole name (2026-11-11)

Row S42 of [EPIC-14](../plan-personas-inbox-voice-and-calls-come.md), started by Jordi when he closed S36. Worker run `run_9690e75c-380d-4d05-8991-695057dfcf83`. A freeze-allowed breakage fix: only how a new page is named changed.

## Where the cut was

`packages/core/src/engine/treePlacement.ts`, `safeTitle()`, used by `writeProvisionalLeaf()` for every new provisional page the filer writes (`Notes/<title>.md`, title in front matter and `# heading`). It kept the **first 8 words**, then `slice(0, 60)` mid-word, then dropped trailing punctuation. Every caller goes through it: the live filing rescue (`engine.ts`), the tree sweep (`treeSweep.ts`), the note linker (`noteLinker.ts`) and `placeCapture`.

## The change

`pageTitle()` replaces it (PR [#1641](https://github.com/zenod-ai/zenod/pull/1641), squash-merged as `b4cf52b`):

- The whole first line is kept, with the same cleaning as before (no `\ / : * ? " < > | # ^ [ ]`, spaces folded).
- Only a line longer than 120 characters or 200 UTF-8 bytes is shortened (this leaves room for ` 99.md` under the 255-byte file-name limit of Drive and git checkouts). It cuts at the end of a clause (`. , ; : ! ?` or a spaced dash) when that keeps at least 60 characters, otherwise between words, never mid-word. Then it drops a dangling small word ("a", "the", "and", "de", "que" and similar).
- Counting is by code point, so emoji and CJK are never split. A single word longer than the limit is the only case that can be cut inside a word.
- Not changed: filing prompts, models, the tree, page format, finding, chat behaviour (root L-6, L-7). Existing pages are not renamed. A same-name page is still found and added to, and the ` 2`, ` 3` suffixes still work.
