## The fix (PR #1706, merged `0930bcfa`, CI green)

- A code request or Settings status read that finds the binding `unavailable` re-runs that account's reconcile once (at most every 30 s per account), then answers. Before: 503. The new test fails with 503 without the change and gets 200 with it.
- The stuck check says `channel_unavailable` (Phylax did not answer, with the error code), `channel_setting_up`, `channel_suspended`, or `our_error` (read failed). It says "missing" only when no binding row exists. The ops route also returns the binding state.
- This applies to every tester account. No account data was edited. His binding heals by itself on the first refresh that reaches Phylax, so no repair was needed.
