## What changed

- `docs/health/s1-live/probe.py` (remote part, runs on VPS1 every 5 min):
  - Traefik access log: read from the byte offset where the last run stopped. The mark is inode + offset + the
    first 256 bytes; logrotate's `copytruncate` keeps the inode, so a shorter file or different first bytes means a
    new day's file, read from the start (same "since the rotation" window as the old whole-file read). The only sudo
    rule is `cat` of the whole file, so already-read bytes still pass through a pipe but are dropped unparsed: no new
    sudo rule was needed.
  - zenod-mt and Phylax container logs: `docker logs --since` the last run instead of the whole 7 days, folded into
    cached counts and last events, pruned to the same 24 h / 7 day windows. A failed read drops the cache, so the next
    run reads the whole 7 days again.
  - Journals: the 14-day deploy roll, the 35-day keeper line and the 24 h watchdog run (13k lines a day) are read since
    the last run, the newest match carried.
  - Cache: `~/.local/state/zenod-health-remote/probe.json` on VPS1 (0600, counts and timestamps only).
- `docs/health/s1-live/timeline.py` (remote part, every 15 min for the last 3 h): the same offset reader for the
  access log with hour buckets cached for 6 h, and container logs since the last run (`timeline.json`, same dir).
- Timers on VPS3 moved off :00/:15/:30/:45: probe `*:03/5`, timeline `*:07/15`, smoke `*:11/15` (+ up to 30 s
  random). The desk note's example `*:02/5` for the probe would start with the timeline at :07/:22/:37/:52, so the
  probe is on :03/5. The smoke battery's six `bash -s` already run one after another (`spawnSync` in a loop in
  `scripts/smoke-prod.mjs`), so its script is unchanged; only its timer moved.
- Tests: `test_probe.py` gains the offset reader (new lines only, half-written last line, copytruncate rotation,
  emptied file, a short file growing) and "folding in parts equals one whole read".
