## Why new reports still reached his pages

The ops-report filter (E9-2h) was not the problem. It recognises all 8 MCP reports of 8 November that were topic-filed onto his pages (02:08 to 15:50 UTC, one of them after `dce775e` went live). All 8 failed the same way:

1. The rollup step picked the long-term root "Zenod (earlier)", whose page `Projects/Zenod/Backlog System Vision & Planning Source` already had a summary over the 480-character limit.
2. The rollup then checked the whole page, failed on that old error (`summary/budget`) and undid itself.
3. Any rollup failure fell back to ordinary topic filing, so the report was written onto his pages as if he had said it.

Reproduced on the vault revision before each report: for all 8, the rollup chooses that page and the check fails only on the old summary. A second path did the same thing: on the capture-then-enrich path the rollup was skipped whenever an earlier filing receipt existed.

The 29 lines under `## Ops rollup` headings come from the same fallback. Topic filing appends at the end of a page, which is after the rollup section, and the S14 report-line planner skipped that whole section.

## What changed (#1526)

| | |
|---|---|
| Rollup check | A rollup is judged only on the errors it adds. An error the page already had no longer blocks it. |
| When a rollup still fails | In a vault with a tree, the report stays in the Log with `filed: log only (agent report, kept in the Log)`. It is never topic-filed. This covers both filing paths, and also when an earlier receipt exists. Vaults without a tree file as before. |
| Report-line planner | Lists report lines under an Ops rollup heading too. Dated rollup lines and his own lines stay. |
| Ranking | Search leaves agent Log entries and the moved-report archive out of the memories it shows, unless the question is about the agents' work (agents, reports, tickets, deploys, epic or row codes, run ids). The weighted graph walk from EPIC-18 follows the same rule. Page text drops only the dated rollup lines (index schema 5, rebuilt once). |

Tests use demo text in the shape of today's real reports. A forced rollup failure shows no report reaches topic filing, and a voice note still files onto its page. The new tests fail on the old code.
