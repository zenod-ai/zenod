## Why no reply went out after recovery

Phylax sends the "Saved" receipt only when `get_task_result` reports the Zenod job `done`. A save refused by the vault guard was stored as `error`, so `get_task_result` said `error`. Phylax's capture journal recorded that as terminal and sent its warning. A later retry would replay the cached error, and Phylax never polled again. #1498's recovery finished the very same jobs minutes later, but nobody was listening.

The reply path itself was not broken. A message arriving after 07:15:43 gets a fresh Zenod job. New voice jobs do not wait behind the stuck `capture_retry_pending` ones (`claimNextVoiceJob` only takes `queued`/`transcribed`). At 07:20Z no WhatsApp message had arrived since 07:14:40, which is why the page still showed 11-04 for the last "Saved" reply.

## Fixes (PR #1499, merged `83434ff`)

1. **Refused saves count as pending, not failed.** `get_task_result` reports a store/media_ingest/enrich_memory job refused with `filing_recovery_pending` as `queued` (`awaitingVaultRecovery`). Recovery requeues exactly these jobs. In a repeat outage Phylax keeps polling: it sends its existing "still filing" reply, then the normal "Saved" receipt once recovery has run. No chat wording changed (root L-6).
2. **Recovery at runtime start.** Hosted tenant runtimes now call `taskJobQueue.resumeAtStart()`. It drains jobs left queued by a restart (hosted runtimes never called `resume()`) and checks the vault 30 s later, so an interrupted filing is recovered without waiting for a save to fail. Test: `vaultRecovery.test.ts` "recovers an interrupted filing when the tenant runtime starts".
3. **Stall alert.** On the health page, row 4 (Phylax) turns red when a WhatsApp message has had no "Saved" reply for over an hour. Row 3 (database) turns red when saves fail and none has finished for over an hour. Red rows go to Jordi's HQ thread through the EPIC-6 S5 sender ([AGGREGATOR.md](../health/AGGREGATOR.md#zal-a8-stalls-turn-a-row-red)). Installed on VPS3 at 07:31Z; it fired on the live stall above.

Tests: server suite 1473 passed, 1 skipped. `test_aggregate.py` 34 OK. `watchdog-logic.test.sh` all pass. CI on #1499 green.
