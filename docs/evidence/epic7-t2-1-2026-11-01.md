## Mechanism chosen, and why

1. **Prevention (operator, no code): extend each month with a `once` 100% coupon.** This has the fewest moving parts. It is one API call per tester per month, it can be applied any time in the period, applying it twice is harmless, and it leaves no lasting state: a missed month simply bills. A trial extension was rejected because `trialing` with no card ends in `paused` or `canceled` when the trial ends, and it shows the tester as "trial", not as an ordinary subscriber. `pause_collection` was rejected because it voids every invoice silently. A forever coupon was rejected because it is not "month by month". Runbook: [epic7-tester-monthly-extension.md](../runbooks/epic7-tester-monthly-extension.md).
2. **Backstop (code, [PR #1447](https://github.com/zenod-ai/zenod/pull/1447)): Zenod tells the user itself.** On the authoritative Stripe refresh, an entitled account that turns `past_due` gets one WhatsApp (else Telegram) notice. One that stops being entitled gets a second notice **before** local and Phylax suspension. Dedupe is per account, kind and period. The copy is fixed, so the Phylax management surface still has no free-text send primitive. These are ordinary-user messages, with no tester branch. Because the past_due notice comes about 13 days before Stripe's cancel, nobody is cut off unannounced, even if the operator forgets.
3. **Fix found on the way (same PR):** both Stripe accounts render events at API `2026-06-24.dahlia`, where `invoice.subscription` moved to `invoice.parent.subscription_details.subscription`. So Zenod's `invoice.paid` / `invoice.payment_failed` handler returned `unmatched` for every live invoice event. State still arrived through `customer.subscription.*`, which hid the bug. The harness shows `unmatched` before the fix and `past_due` after.
