**Why the 11-04 media got 404.** Phylax signs every staged media link with a 24-hour expiry (`phylaxUnit.ts`, `expiresAt: Date.now() + 24 h`). An expired link gets the same `404 {"error":"not found"}` as a missing file. The 11-04 10:32Z media save was blocked by the A8 filing outage and replayed about 45 hours later, after its link had expired. **Fix:** links now last 7 days (`PHYLAX_ARTIFACT_LINK_TTL_MS`), which covers the vault-recovery replays (A8) and the voice retry window (A10, about 24 h). Test: "keeps a staged media link valid for a replay days later (ZAL-A16)".

**Lost, as far as agents can recover:**

Recovering it needs root on VPS1 to read the job's file name and re-sign the link. Agents do not have that access: `sudo` is allowlisted and the volumes are root-only. Parked below.

## 2. "Saved" receipts after a restart

**Cause.** `PhylaxPortedRuntime.start()` sent undelivered receipts right after creating the WhatsApp socket, before it had opened. Baileys threw `Connection Closed` (05:45:36Z today, receipts `ACA8…5B04` and `3B40…FA7F`). The delivery claim was taken before the send and stayed set, so nothing ever retried them. Receipt recovery (`recoverPortedReceipt`) also sent on the connecting socket, and that failure tore the socket down.

**Fix (#1558).**
- While WhatsApp is not connected, a terminal receipt throws `PhylaxChannelNotConnectedError`. That releases the claim, the same way an allowance pause does.
- Recovery never sends on a socket that has not opened.
- Each time the link opens, after its own outbound recovery, Phylax retries the held receipts (`onConnected` → `resumePendingCaptures`).
- If two recovery paths pick up the same pending receipt, it is sent once.

New log lines, ids only: `terminal_receipt.deferred`, `terminal_receipt.retry_after_reconnect`, `terminal_receipt.sent`.

**Tests.**
- New: "holds Saved receipts finished during a restart until WhatsApp reconnects, then sends each once (ZAL-A16)". Two receipts finish during a restart on a socket that throws `Connection Closed` until it opens. The test checks that nothing is sent, nothing fails and no claim is kept; that both receipts go out once on open; and that another reconnect sends nothing.
- Existing tests whose fake sockets never opened now open them.
- Server suite: 1619 passed, 1 skipped. `ci` green on #1558.
