# Why the promote gate failed on Jordi's newest notes

**Cause: the test, not his notes.** One filing hit a publication conflict inside the suite's throwaway copy, and that blocked the copy. The suite had none of production's self-healing, so it refused every later save. One event became 9 agent errors and 10 retrieval misses.

**Now:** on staging 57ea125 with the fixed suite, his newest notes (vault fe392d4) score **ingestion 94.1%, retrieval 98.2%, errors 3.1%**, above the floor of 85, 90 and 10. The demo set scores 96, 100 and 1.7. Production stays on d9ebdd6. The fix changes only the test, so nothing waits for a promote because of it.

Both vault revisions gave the same numbers on the same build, so the newest notes don't move the score. The two reruns at load 50 failed on time instead: on an 8-core box, every filing ran past the suite's 3-minute limit.

## What was checked

- **The vault copy is complete:** 1203 of 1203 files from git. The 25 commits since 6a5a370 only add notes and update pages.
- **Questions are unchanged:** all 47 gave the same result in the failed gate and in the rerun. The retrieval drop came only from the 9 agent searches that had nothing to find.
- **His notes file cleanly:** the conflicting note filed fine alone, and all 8 judged notes filed fine in the gate's order on vault a7774a6. The conflict did not happen again.
- **Production is clean:** 0 publication conflicts and 0 vault recoveries in the zenod-mt logs over the last 48 h.
- **Production would heal it:** a simulated conflict, handled by production's own recovery code, clears the block, and the next save works.

## The fix

The fix merged as [#1632](https://github.com/zenod-ai/zenod/pull/1632) (c48d66a). It changes only the test and the promote script. The engine is untouched.

- When the vault blocks a save, the suite now runs production's own recovery and retries once. The note that conflicted still counts as one error, and the run records the recovery.
- The promote script copies each vault into a temporary folder and renames it into place, so a copy that is cut short can't stand in for that revision.
- The promote script waits up to 20 minutes for the box's load to drop to its core count before running the timed sets.
- Checked on the demo set: 96 / 100 / 1.7, unchanged. With one injected conflict it scores 92 / 100 / 3.4: one error, recovery ran, and nothing cascaded.

Model spend: $0. The suite uses the free stand-in model.
