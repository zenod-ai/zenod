Era 1 — what we're building right now

Yes, your mental model is right: Phylax is a tiny layer-1 router. It routes by shape, never by meaning. Three rows, that's the whole router:

🎙️ Voice noteany voice, always
→
Store to memory — transcript saved verbatim, receipt back with recap + commit linkZenod's librarian files it and may ask one filing question
💬 Textany text, always
→
Ask memory — read-only Q&A about what's storedyour question about the last note is scoped to that note's evidence
📷 Image / docany media, always
→
Ingest to memory — same as voice, via the media pipeline
The rule you hold in your head: speak to capture, type to ask.
Honest consequence you spotted: if you reply with a voice note, it stores again — yes. Voice never routes to Q&A in era 1. That's the price of a router with zero language understanding, and it's cheap: git is the undo. If typing questions ever gets annoying, that's the signal to build era 2 — not to add cleverness to the router.

What's scoped — the safety wall

The WhatsApp connection holds one token. That token can only see memory tools. Nothing is "refused" — dangerous tools simply don't exist on this connection.

✓ The token can touch

  • store_memory
  • ingest_memory
  • search_memory
  • ask_brain (read-only)
  • get_task_result (receipts)
Worst possible outcome: an extra note in a git vault. Undoable.

✗ Does not exist here

  • run_task / create_issue
  • backlog_*
  • tweet / publish / send
  • delete anything
"Post a tweet" can't happen — not because a guard read your words, but because there is no tool to call. The wall is the safety, and it never misreads you.

Era 2 — where the Ring comes back, and how actions work

When you actually need actions from chat, exactly one row changes. Voice and media stay mechanical forever.

🎙️ Voice note
→
Store to memory — unchanged, untouchable
💬 Text
→
Ring agent (small, no guard) — reads memory, answers, and can draft actionsevery action becomes a held draft: "Here's the tweet — reply yes to send." Your "yes" releases it to the actuator. No draft, no action.
Actions = one swapped config row + held drafts. Not a new architecture. The Ring returns as a small agent in the text row — never as a gatekeeper over capture.

Who is who

PhylaxThe doorman. Owns WhatsApp/Telegram, transcribes, routes by shape. Never thinks.
ZenodThe memory. Stores, files, answers questions about itself. Never calls anyone. Never acts.
RingThe future front-desk agent. Parked today — nothing routes to it. Returns in era 2 in the text row.
CallisthenesThe mouth. The only thing that posts to X. Not the Ring — an actuator agents call, with drafts-never-send built in. You never talk to it directly.
EpaminonThe hands. Runs execution work. Also parked from chat's point of view.

Your questions, straight

"So the text one is directed to the Ring?"
No — correction. In era 1, text goes to memory Q&A. The Ring gets nothing. It's parked, whole, untouched, waiting for era 2.
"So we're always talking to the memory in the end?"
In era 1: yes, deliberately. Capture + recall is the product you actually need this week — it's what the two waiting voice notes are. Everything you say lands in or reads from one place, which is exactly what makes era 2 agents useful later: memory is already full.
"I still have no ability to trigger actions."
Correct, and it's a feature of era 1, not a gap: every incident you've had came from machinery that interprets. Era 1 ships only machinery that holds. Actions return in era 2 as held drafts — the one action pattern in your whole codebase that has never failed you (Callisthenes' C-22).
"Why are you so convinced?"
Because this splits the system by failure cost. Mechanical lane: mistakes are impossible. Q&A lane: mistakes cost one bad answer. Draft lane (era 2): mistakes cost one "no". Nothing anywhere can lose a 20-minute note again.
