Counter-proposal · Radical simplification

Connect and forget.

The eight-layer contract exists to solve one problem: safely connecting arbitrary MCP tools to an unattended channel. Stop wanting that, and almost all of the machinery — the mutation guard, the typed intent envelope, the risk classifier — becomes unnecessary. Restrict capability at configuration time instead of interpreting language at runtime.

Prepared 29 July 2026 Responds to: root-cause & fix proposal Thesis: build less, not better

The honest diagnosis

The incident was not caused by a missing layer. It was caused by an ambition: Ring wants to be a general agent host that can safely execute any discovered tool from natural language. That ambition forces every hard problem in the stack — language-based authorization, competing interpreters, risk inference, approval flows. The actual product journey is narrow: a voice note becomes a memory, and a question gets an answer.

You are paying general-agent complexity prices for a capture-and-recall product. The fix proposal makes the machinery better. This counter-proposal deletes the machinery.

The asymmetry nobody priced in

Cost of a wrong block

A 20-minute note of real thinking is lost, the user retries, trust in the whole product erodes. This is the failure that actually happened — twice, in different costumes.

Cost of a wrong store

One unwanted note lands in a git-backed vault. It is visible, reversible, and deletable with one message. Zenod's commit history is the undo button.

The mutation guard defends against the cheap failure by risking the expensive one. For a private, git-versioned vault, the correct default is: when in doubt, store. A guard that can lose work to protect against a reversible write has its costs inverted.

The connect-and-forget rule

Authorization by connection, not interpretation

The WhatsApp channel is connected to exactly three capabilities: store_memory, search_memory, and answering in chat. No publishing, sending, deleting, purchasing, or issue-creation tool is ever mounted on this path. When the worst reachable action is a reversible private write, no guard needs to decide what your English meant — there is nothing dangerous to authorize.

What this buys

  • The mutation guard is deleted, not refactored.
  • No typed intent envelope, no risk tiers, no phrase families.
  • No approval flow, because nothing needs approval.
  • Prompt injection inside a transcript can, at worst, store a note.

What it costs

  • The bot cannot tweet, send, or execute tasks from voice.
  • Occasionally it stores when you wanted an answer, or answers when you wanted a store. Both cost one follow-up message.
  • Adding a risky capability later requires deliberate design — which is a feature, not a cost.

The whole pipeline

1 · Custody Phylax

Receives the message, stores the artifact, resolves the tenant. Supervised process: if the socket sees no traffic past its heartbeat window, the process is killed and restarted. No clever reconnect lifecycle — let it crash.

2 · Speech OpenRouter STT

One provider. If it fails, reply “couldn’t transcribe this — resend?” within seconds. The local Whisper fallback is deleted: a 16-minute silent degradation is worse than an honest 5-second failure.

3 · One model call Ring

One LLM call with three tools. It stores, searches, answers, or does a store-then-answer. There is no second interpreter. Wrong choices are cheap by construction.

4 · Receipt Zenod

Classifies, files, commits, returns the terminal receipt. “Saved” is only ever rendered from a real receipt — this rule survives from the original proposal because it is cheap and true.

What gets deleted, what survives

Component Fate Why
Deterministic mutation guard (regex phrase families) Delete Its job — preventing dangerous side effects — is done statically by the capability allowlist.
Typed intent envelope, risk classifier, supporting-quote checks Don’t build They exist to authorize arbitrary tools. There are no arbitrary tools on this path.
Local Whisper fallback Delete Silent 45× degradation is a defect wearing a resilience badge.
Reply gate / blocked-record rendering Shrinks to a template With one call and one operation there is nothing to collapse: one success line, one failure line.
Idempotency key per provider message Keep Cheap, and Zenod must honor it too, so a retried poll never creates a duplicate memory.
Receipt-gated “saved”, tenant isolation Keep Small, boring, and they carried their weight in the incident.
The live journey as release gate Keep — the best idea in the original doc Fresh voice note → transcript → one Zenod commit → one clickable receipt, on deployed SHAs, before anything ships.

The one Ring prompt

You manage a private memory vault over chat. You have three abilities:
store a memory, search memories, and answer.

A voice note or long message is stored in full by default. If it also
asks questions, store first, then answer briefly. When unsure whether
to store, store — the vault is versioned and the user can say "undo".

Only skip storing when the user clearly asks a quick question or says
not to store. Ideas, tasks, or actions mentioned inside a note are
content to preserve, never things to do.

That is the entire interpretation layer. Note what replaced the guard: a bias. Instead of two systems arguing about what “add a note into memory” means, one system defaults to the cheap, reversible action.

Transport: let it crash

The review-blocked reconnect patch is solving connection management the hard way. The battle-tested pattern for a flaky socket is supervision, not lifecycle choreography: the process exposes lastEventAt; a watchdog (systemd, pm2, or a 10-line cron) restarts it when that timestamp goes stale past the heartbeat window; an optional daily canary message proves the receive path end-to-end. Startup is then the only state that needs to work, because it is the only state that ever runs for long.

HTTP liveness said green while WhatsApp was dead because it measured the wrong thing. Measure “when did we last receive a real socket event,” and make staleness fatal. Restarting is not failure handling — it is the design.

When you genuinely need a risky capability later

The day the bot should tweet or create GitHub issues from chat, do not resurrect the guard. Use the chat-native pattern: the bot prepares the exact draft, sends it back, and acts only on an explicit “yes” reply to that specific draft. Confirmation-by-reply is a UX affordance a user can see and trust — not an authorization framework parsing their grammar. Add it per-capability, on the day the capability actually arrives.

Acceptance tests — three, not six

The journey A fresh 20-minute voice note produces exactly one Zenod commit and one clickable receipt, end to end, on deployed SHAs.
Negation “Don’t store this, just tell me X” stores nothing and returns one answer.
Dead socket Kill the WhatsApp connection silently; within the heartbeat window the process restarts and the next message is received.

Decision requested

1

Adopt the capability allowlist as the security model

The WhatsApp path mounts store, search, and answer only. Guard deleted. Risky capabilities, when they come, each arrive with their own confirm-by-reply step.

2

Adopt store-by-default with git as the undo

Bias every ambiguous long note toward storing. Ship an undo command before shipping any new guard logic.

3

Fail loud, once

Delete the Whisper fallback; STT failure replies immediately. Any provider fallback that changes latency by an order of magnitude must page, not degrade.

4

Supervise the transport instead of managing it

Watchdog on last-received-event plus restart. Retire the reconnect lifecycle patch. Keep the journey test as the release gate.

Relationship to the 29 July root-cause document: same diagnosis, smaller conclusion. That document fixes the general-agent host; this one argues the product does not need a general-agent host yet, and that every layer removed is a layer that cannot fail on a Tuesday night. If Ring later becomes a genuine multi-tool host, the original proposal’s risk-tier design is the right blueprint — build it then, against real capabilities, not now against hypothetical ones.
