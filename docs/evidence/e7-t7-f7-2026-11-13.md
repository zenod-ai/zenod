## Why the repeat question read 97K

Production logs (container `fc150d9a`, VPS1 sudo allowlist `docker logs --since 02:44:30Z --until 02:52:00Z`, no content):

- 02:47:36.8Z the request arrives (`duration_ms 124989`, completed 02:49:41.8Z).
- 02:48:39.5Z `[llm-cost] operation=tasking` (briefing only 993 tokens): about 63 s passed before the answer loop began, while the account's `/api/vault` reads were taking 5 to 13 s each (busy Drive vault, the same path T7-F6 works on).
- 02:51:01.7Z one `[llm-usage] operation=answer … input=97105 output=642 cache_read=35513`: one answer call. Its tool loop (`DEFAULT_MAX_STEPS = 8`) ran every round, and each round re-sent the whole context (system rules, history, tool results), so the input grew round on round. Questions 1 and 4 used 2 to 3 rounds (21,587 and 39,138).
- The edge is Cloudflare (`server: cloudflare`), which drops a request with no response after 100 s.

So the cause was the tool loop, with history and retrieved pages growing each round, and no limit except the round count.

## Change (#1654)

- `packages/core/src/llm/aisdk.ts`: `ANSWER_INPUT_TOKEN_BUDGET = 48_000`, `ANSWER_TIME_BUDGET_MS = 45_000`. Once the input read so far plus the last round's input would pass the budget, or the loop has run 45 s, the next round is the final one. It uses the same rules as the step cap: no tools, or `submit_memory_answer` only for memory answers. Round usage is now counted on every answer, not only cancellable ones.
- `packages/server/src/app.ts`: `CHAT_REPLY_DEADLINE_MS = 90_000`. A slower turn replies with a plain "still working" line and keeps running; a late failure is logged.
