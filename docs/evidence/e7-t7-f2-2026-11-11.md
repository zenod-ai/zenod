## Change

PR [#1636](https://github.com/zenod-ai/zenod/pull/1636) (branch `wt/t7-f2`). `scripts/tester-watch/tester_watch.py` now also reads Zenod's own tester list, `tester-flow.json` (plus `tester-marks.json`) on the `zenod-mt-data` volume — the same file `packages/server/src/testerFlow.ts` keeps and cloud.zenod.dev/admin/testers shows. Each applicant is listed after the ledger's testers, tagged `apply` (`apply, test` for our own tests), matched to its account by the Stripe promotion code on the subscription, the account that redeemed a Zenod-made code, or email, and gets the same columns and `--check` alerts (sign-up, plan, usage vs cap, last activity). Waitlisted and not-yet-signed-up applicants get a row too. The ledger keeps working; an account in both is one row (`ledger, apply`). `--redact` masks applicant emails, codes and ids.

Access: the file sits on the volume tester-watch already reads as root, and there are no new flags, so today's sudo rule (`/usr/local/bin/tester-watch` with `--all|--json|--check|--redact|--no-stripe|…`) covers it. No new read rule is needed.
