## Result in one paragraph

Each tenant's AI spend can now be capped for real. Once `ZENOD_TENANT_MONTHLY_ALLOWANCE_USD` is set on `zenod-mt`, a tenant over it gets no AI call. The model call is stopped before the provider is contacted. On WhatsApp the user gets a reply saying why and when the allowance resets. The console usage card shows the AI and messages/voice lines and goes *paused* at the cap. The Phylax message/voice allowance already sent a throttled notice when it ran out (live since `ea73076`), so T1's "silent" finding was too strong. Its wording ("Phylax credit") is fixed in code and goes live with the next Phylax roll. **Nothing is capped in production yet**: the figure is ask E7-A2 (below). Until it is set, the new code behaves exactly like before.

## What #1446 changes

- `packages/core/src/llm/aisdk.ts`: adds `LlmAllowanceExceededError`. The `onBeforeCall` hook may throw only that error; every other metering error is still swallowed. `classify` keeps the error type instead of rewrapping it.
- `packages/server/src/runtime.ts`: `aiAllowanceStatus`, `aiAllowanceBlock`. `checkTenantAllowance` now throws in enforce mode (the default once an allowance is set). `ZENOD_TENANT_ALLOWANCE_MODE=shadow` keeps it log-only. Applies only on the hosted platform key; self-hosted keys are never capped.
- `packages/server/src/taskJobQueue.ts`: the gate runs at job start:
  - `chat`: done, with the reason as the reply text. The engine is never started. A cap reached mid-turn gives the same reply.
  - `media_ingest`: the original is archived raw (no AI). The receipt has `code: ai_allowance_exhausted` and explains that the file was not read or filed.
  - Other kinds: error, with the reason as the message.
- `customerMetering.ts`, `zenodPhylax.ts`, `hosted-usage-card.tsx`: the card shows "AI processing: N% of this month's allowance" (no line when no AI cap is set) and "Messages and voice: N%". It shows percentages only, keeping the existing customer-safe rule of no dollar figures. State is *paused* at an enforced AI cap.
- Phylax side, live on the next Phylax roll: an `ai_allowance_exhausted` receipt is passed through word for word instead of "Saved ✓ / Recap: …". The notice text now reads "You have used this month's message and voice allowance on your plan…".
- A startup warning fires when AI capacity plus the Phylax allowance exceeds the master units (see the trap below).

What the user sees at the AI cap (WhatsApp, via the live Phylax):

> ⚠️ You have used this month's AI allowance on your Zenod plan, so I can't process this message. It was not saved. Your allowance resets on 1 December 2026; please send it again then.

## Trap found: the AI figure and the master units must be set together

`zenodPhylax.ts` treats the AI allowance as `USD × ZENOD_ALLOWANCE_UNITS_PER_USD` units carved out of `ZENOD_MASTER_ALLOWANCE_UNITS`. If AI plus Phylax exceeds the master, Phylax refills are refused and the reconcile reclaims the wallet (`excess` in `zenodPhylax.ts`), which pauses WhatsApp. With today's master (3,000,000), a $3 AI allowance alone would do this. #1446 logs a warning; the ask below sets both figures together.
