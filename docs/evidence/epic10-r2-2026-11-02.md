Zenod side: `/oauth/register` accepts any redirect URI, and the authorize page's CSP allows loopback `http://127.0.0.1:*`, `http://localhost:*` and any https callback (`packages/server/src/zenodUnit.ts`). So the Cursor desktop (`http://localhost:8787/callback`), Gemini CLI loopback and VS Code flows are not blocked by CSP. No client was run end to end from a signed-in account here; that is R5's Claude test (and E7-A11's browser sign-in).
