# E15-Q0 — Cheap model provisioning for memory tests (proposal)

Date: 2026-11-08 · Run: run_7702b24b-9558-4ab5-9e86-983d446f2f3f · Epic: EPIC-15 (memory answers: quality check and real-life tests)

Jordi asked (on E15-A1): "We need a conversation about enabling open code with DeepSeek flash41 as provider. We need to think about how to provision this efficiently so it doesn't become expensive." This page is that conversation's starting point. Nothing was bought, no key was made, no limit was changed.

## Recommendation in one paragraph

Give the tests their own **OpenCode Go** workspace ($10 a month, Extra Usage left off, so it can never cost more than $10) and run every DeepSeek test call through it, including agents running evals through the OpenCode CLI. The plan includes $100 a month of DeepSeek V4.1 Flash usage, about ten times what our tests use. Keep one small **OpenRouter test key capped at $5 a month** only for the Gemini 3.1 Flash Lite calls that production's chat answers use, because OpenCode Go does not offer that model. Hard ceiling: **$15 a month**, against about $20 to $40 a month uncapped today. Tests then never touch the OpenRouter key and account that production depends on.

## 4. Recommendation: (c) plus a small (a), hard cap $15 a month

1. **A team OpenCode Go workspace "zenod-tests", $10 a month, Extra Usage off.** All DeepSeek test calls go through it: filing runs, `ask_brain`, a DeepSeek run of the chat set, and agents running evals with the OpenCode CLI. A separate workspace keeps Jordi's own subscription and his Mac out of it.
   - Provisioning on the servers: one key stored on VPS1 as `OPENCODE_GO_API_KEY` (class shared, app `zenod-tests`). It never goes into any Dokploy app, so production cannot read it.
   - Agents use it through `secret run opencode-go -- …`. The OpenCode CLI on each VPS3 seat gets the `opencode-go` provider with `deepseek-v4.1-flash` as the default model and reads the key from the environment, so the key never sits in a seat's config file.
   - The test runner points at OpenCode Go's OpenAI-compatible endpoint, sends its own user agent and a stable `x-opencode-session` header per run, as the Go docs ask.
2. **One OpenRouter key "zenod-tests" with a $5 monthly limit**, only for the Gemini 3.1 Flash Lite chat answers (about 45 calls a run, about $0.07). The tests stop using the shared `OPENROUTER_API_KEY`.
3. **Usage watch, alert at 80 percent.** The runner logs tokens and cost per call to `~/zenod-eval/usage.jsonl`. A daily check sums the month so far against the Go allowance ($80 of $100) and reads the OpenRouter test key's `limit_remaining` ($4 of $5), then posts an alert to the console when either passes 80 percent. Above the cap, calls simply fail. Nothing ever auto-tops-up.
4. **Why not (b)?** It is about as cheap, but it means a new account, a prepaid balance to watch and peak-hour prices, all for less than Go's flat $10 covers. **Why not (a) alone?** It costs about twice as much and keeps tests on the account production lives on.
5. **Caveat:** production routes Flash through OpenRouter's hosts, while Go uses its own. Same model weights, but answers can differ slightly. Every release check still runs once on the production path itself.

## 5. What Jordi would do (about 5 minutes, one sitting)

1. At [opencode.ai](https://opencode.ai/auth), create a workspace named **zenod-tests**, subscribe to **Go ($10 a month)**, leave **Extra Usage off**, switch on the **Global** region under Settings › Privacy (DeepSeek needs it), and create one API key. Paste it into the private secret card the team sends. Never paste it into chat.
2. At [openrouter.ai/settings/keys](https://openrouter.ai/settings/keys), with the management key, mint a key named **zenod-tests** with a **$5 monthly limit** and paste it into the second secret card.

The team does the rest: stores both keys, moves the runners off the shared key, sets up the OpenCode CLI on the seats, and adds the 80 percent alert.

## 6. How production stays apart from test spend

- Tests no longer use `OPENROUTER_API_KEY`, so test spend no longer draws down the account production lives on.
- Neither test key goes into Dokploy or any production container. Production keeps `ZENOD_PLATFORM_OPENROUTER_KEY` and its $26 cap.
- Each test key has its own hard limit ($10 flat on Go, $5 on OpenRouter), and neither can spill into production's budget.
