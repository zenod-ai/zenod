### 5. What is wasteful, and what is not

- **Wasteful: one key shared by tests and four apps, with no limit and no log.** $43 before November and $3.20 today cannot be attributed. Round 1's fix (tests on their own capped keys, E15-A2) also makes this visible.
- **Wasteful: filing on a big vault.** It can take 14 minutes and costs up to about 10 times the small-vault price, and it splits one note into many small pages (E15-Q1 cause 6, near EPIC-12 S8). Fewer and smaller calls per note would cut the biggest production cost.
- **Wasteful: `ask_brain` timeouts.** The caller gives up at the timeout but the loop finishes and bills. 3 of 4 live asks today were paid for and never seen (E15-Q1 cause 5).
- **Wasteful: thrown-away test runs.** Model comparisons that end when the credit runs out are paid for but give no result. A capped test key stops them before they start.
- **Already fixed: agent reports.** On 1 Nov, 83 agent reports were filed into Jordi's vault through the model. Since 2 Nov they become a free roll-up line (187 so far).
- **Not wasteful:** chat answers (0.2 cents), transcription (0.3 cents per minute), and the weekly sweep (once a week).

### 3. Recommendation

**For Zenod users (their own subscription pays):**

1. **Do not build "Connect your Claude account".** It breaks Anthropic's terms and would be cut off.
2. **Build "Connect OpenRouter" (OAuth PKCE)** as the bring-your-own option: about 1 to 2 days, no new keys on our side, and the user pays their own usage at OpenRouter's prices (about $0.15 to $0.25 per million input tokens on the models Zenod uses, cents a month for a normal user). It is the only one-click, sanctioned "your account pays" button that works with Zenod's models today. Users who do not connect stay on the platform key and the free pass, as now.
3. **Tell Claude subscribers about "Add Zenod to Claude"** (already live). For answering questions, that is the closest thing to "my Claude pays", and nothing needs building.
4. **Later, optional:** a "Use my Anthropic API key" field for Max subscribers who want their monthly API credit to pay, once someone checks Claude models for filing quality and cost. "Sign in with ChatGPT" only if Jordi wants to apply to OpenAI's partner trial.

**For our own test runs:** round 1's recommendation stands (below): **OpenCode Go "zenod-tests" $10 + OpenRouter test key capped at $5 = at most $15 a month.** The tests must use production's models (DeepSeek, Gemini Flash Lite) to mean anything. Running Zenod's engine on the team's Claude seats would break the same Anthropic rule (seats are for Claude Code, not for powering our product), and the Max API credit would only buy Claude models. One change from round 1: OpenRouter OAuth would let Jordi sign in once and **connect a test key to a separate OpenRouter account**, so test spend never touches production's account.

## 4. Recommendation: (c) plus a small (a), hard cap $15 a month

1. **A team OpenCode Go workspace "zenod-tests", $10 a month, Extra Usage off.** All DeepSeek test calls go through it: filing runs, `ask_brain`, a DeepSeek run of the chat set, and agents running evals with the OpenCode CLI. A separate workspace keeps Jordi's own subscription and his Mac out of it.
   - Provisioning on the servers: one key stored on VPS1 as `OPENCODE_GO_API_KEY` (class shared, app `zenod-tests`). It never goes into any Dokploy app, so production cannot read it.
   - Agents use it through `secret run opencode-go -- …`. The OpenCode CLI on each VPS3 seat gets the `opencode-go` provider with `deepseek-v4.1-flash` as the default model and reads the key from the environment, so the key never sits in a seat's config file.
   - The test runner points at OpenCode Go's OpenAI-compatible endpoint, sends its own user agent and a stable `x-opencode-session` header per run, as the Go docs ask.
2. **One OpenRouter key "zenod-tests" with a $5 monthly limit**, only for the Gemini 3.1 Flash Lite chat answers (about 45 calls a run, about $0.07). The tests stop using the shared `OPENROUTER_API_KEY`.
3. **Usage watch, alert at 80 percent.** The runner logs tokens and cost per call to `~/zenod-eval/usage.jsonl`. A daily check sums the month so far against the Go allowance ($80 of $100) and reads the OpenRouter test key's `limit_remaining` ($4 of $5), then posts an alert to the console when either passes 80 percent. Above the cap, calls simply fail. Nothing ever auto-tops-up.
4. **Why not (b)?** It is about as cheap, but it means a new account, a prepaid balance to watch and peak-hour prices, all for less than Go's flat $10 covers. **Why not (a) alone?** It costs about twice as much and keeps tests on the account production lives on.
5. **Caveat:** production routes Flash through OpenRouter's hosts, while Go uses its own. Same model weights, but answers can differ slightly. Every release check still runs once on the production path itself.
