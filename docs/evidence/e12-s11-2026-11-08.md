# E12-S11 evidence: dark mode harmonised, light/dark/system toggle (2026-11-08)

Trigger: Jordi on the live console, "in dark mode this needs to be harmonized ux, also we need dark light toggle ux default system".

## What changed (styling only, L-6: no chat behaviour touched)
- `apps/web/src/index.css`: the paper language (`.zp`) gained a dark variant under `.dark .zp`: warm near-black ground `#15130f`, lifted card `#23201a`, warm off-white ink `#ece6d8`, deep green lightened to `#86c9a5` for text and links. Filled green (your bubble, Ask) is a separate `--zp-fill` (`#1f4d3a` light, `#2d6a4e` dark) so white-ish text on it keeps contrast. Light values are unchanged.
- The "Ask your memory." heading and subtitle were dark ink on a black page; they now use the dark ink.
- `apps/web/src/components/theme-toggle.tsx` (new): Light / Dark / System radio group with aria-labels, in the hosted console header (next to Landing / Log out) and the account page header.
- `apps/web/index.html`: inline script applies the stored theme (key `theme`, default system) before first paint, no wrong-theme flash.
- `ThemeProvider` already defaulted to `system`; added `useOptionalTheme` so the toggle renders nothing in isolated test renders.
- Other tabs: audited for hard-coded light colours; the rest use theme tokens. The WhatsApp QR keeps a white tile on purpose (scanning needs it).

## Checks (apps/web)
- `npm run typecheck`: clean.
- `npm test`: 24 files, 146 tests passed.
- `npx eslint` on the touched files: clean. Whole-package `npm run lint` has 7 errors in files this change does not touch (`mcp-tokens-card.tsx`, `KeysTab.tsx`, `McpConfigTab.tsx`, `OperatingRulesTab.tsx`); same count on a clean main.
- Browser run (Playwright against vite on 127.0.0.1, API mocked, server stopped afterwards): with system dark the page loads dark with nothing stored; clicking Dark stores `dark` and survives reload; Light and System switch the class live.
