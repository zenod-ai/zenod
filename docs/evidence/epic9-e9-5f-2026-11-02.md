## What the skill gained

- `skill/epic-spine/scripts/spine_tree.py` (stdlib only, 198 lines):
  - `heat(events, today, half_life=14)`: Σ weight × 0.5^(age/14), events in the future or older than 120 days add nothing, rounded half-up to 3 decimals. Same formula and constants as Zenod's `treeDiscover.ts` (`DEFAULT_HALF_LIFE_DAYS = 14`, `HEAT_HORIZON_DAYS = 120`, `Math.round(heat * 1000) / 1000`).
  - `match_ids(previous, current)`: stable ids across re-derivations, Jaccard ≥ 0.5, one-to-one, greedy best-first; unmatched sets get a deterministic `n-<sha1[:8]>`. This is the rule E9-5b ports.
  - `recent_changes(previous, current)` and `rollup_recent(...)`: added, retired, renamed, moved, regrouped, rendered as `- <day> · <text>` bullets, newest first, 20 kept; a NOOP run changes nothing. This is the `## Recent changes` E9-5c writes.
  - `spine_activity(repo, spines)`: a spine's heat from distinct days of three sources: commits touching the file (one `git log` per scan), dates in Current State `Last attempted:`, and each Issue Ledger row's latest date.
- `spines.py --active`: open goals hottest first, each line ending `— heat <h>`; the fields before it and the closing `next: EPIC-<n>` line are unchanged. `--json` adds per node `heat`, `last_activity`, and top-level `ranked`; node order is unchanged; the 14-day `stale` flag and the `attention:` line are unchanged. Cost: one extra git call per scan (zenod 0.69 s → 0.93 s, agent_team 1.09 s → 1.34 s).
- `references/tree-library.md`: the algorithm contract both sides keep consistent.
- `assets/tree-library-parity.json`: inputs with expected outputs (8 heat, 6 id-matching, 2 Recent-changes cases); `tests/test_spine_tree.py` checks the library against it, so Zenod's port can test against a copy of the same file.
- `references/steward-persona.md`: the steward wake (reconcile; the human's steering first; at most N changes, NOOP default; one revertable change set; report), budgets (changes, money, questions, cadence), the "never" list, and a Delivery Manager vs memory-keeper mapping, written from agent_team's Delivery Manager and Unblocker remits and the E9-4 keeper design.
