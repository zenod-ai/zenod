**Applier rules:**
- It never deletes; `merge-into` appends the source to the target and archives the source with `merged-into:`.
- It refuses to write `Log/`, `_attachments/` or `.git/`, and refuses a commit that deletes a file.
- Re-filed captures become one dated line each on a node page that the migration itself creates. Re-filing therefore never edits an existing page.
- Capture text is read from the vault at apply time and never stored in the plan, so the public repo holds no capture content.
