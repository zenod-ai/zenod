## What #1461 does

| Piece | Where | What it does |
|---|---|---|
| Tree outline | `packages/core/src/vault/treeOutline.ts`, engine `memoryTreeOutline()` | Reads the tree live from `Tree.md` plus each page's `parent:` (E9-2a schema, `buildTreeIndex`). It returns two level-0 groups (Working memory first, then Long-term memory), the Tree.md roots under them, and nested pages below. Each node carries its subtree page count, the newest capture in the subtree (newest Log citation date, else `updated:`/`created:`) and a vault link (GitHub/Drive URL when the provider has one). It carries titles, paths, dates and the one-line Tree.md root summaries only, never a page body. It returns `null` when there is no Tree.md. Pages whose lineage reaches no root show only as a count (`unplaced`). Because the read is live, pages the librarian files (E9-2b) appear on their own. |
| Endpoint | `GET /api/console/memory-tree` in `packages/server/src/customerLayer.ts`; `packages/server/src/consoleMemoryTree.ts` | The tenant comes from the signed-in customer session only (`resolveActiveTenantForUser`, the same path T2.5 Recent saves uses). No session gives 401, no account 404, no runtime 409. No Tree.md or no vault connected gives `{status:"empty"}`. Other errors give 503 and are logged with the tenant id only. Each tenant has its own 60 s cache, keyed by tenant id, and failures are never cached. |
| Tab | `apps/web/src/components/memory-tree-card.tsx`, `MemoryTreePanel` in `ZenodPortalPanels.tsx`, `memory` section in `Settings.tsx` / `dashboard-navigation.ts` / `zenod-edition.ts` | The tab is **Memory**, hosted edition only (self-hosted falls back to Overview). It uses agent_team's epic-tree look: 20 px indent per level, chevrons, a sky dot for Working and violet for Long-term (solid for groups and roots, hollow for pages), an amber ring plus a "provisional" badge for provisional placements, and mono page counts. Each row shows "latest <date> · <short title of the newest page>". Levels 0–1 are open on load (groups show their roots) and deeper levels open on expand; there are also Expand all and Collapse buttons. Clicking a root or page shows "Where it sits: Working memory › … › page" and an "Open in your vault" link (or the path when there is no link). Root summaries show at levels 0–1. A vault without a tree shows "Your memory tree appears as Zenod files your captures." A failing endpoint shows "temporarily unavailable. Your notes are safe in your vault." |
| Bundle guard | `bac8ed5` | `consoleMemoryTree.ts` imports `runtime.ts` as a type only, so the Phylax bundle stays clean (`scripts/assert-phylax-bundle.mjs`). |

Gaps:

- **G1 (fixed, #1465):** `apps/web`'s `test` script lists its test files one by one, and #1461 added `memory-tree-card.test.tsx` without adding it to the list. CI therefore never ran the tab's UI tests. #1465 adds it.
- G2 (small, no change): the "latest" label names the newest *page* in the subtree, not the capture text. This matches "latest capture per node" well enough and avoids showing note content.
- G3 (small, no change): pages deeper than `MAX_TREE_DEPTH`, or in a parent cycle, are dropped from the outline and only counted in `unplaced`. The prod tenant has `unplaced 0`.
