## 1. What was built (`packages/core`)

| Piece | Where | What it does |
|---|---|---|
| Parser and planner | `engine/steerMessage.ts` (pure) | Reads six phrasings in English, Spanish and Catalan: "pin X", "rename X to Y", "X is Y", "X is not Y", "that's wrong" and "yes, close X". It resolves the root by id, name or alias, ignoring case, accents and `_`, and otherwise by every word of the name. A root it can't find, or one that matches several, gets a short question back, never a guess. An ordinary sentence that only looks like a steer stays normal chat. Plain "X is Y" counts only when Y is a root and X is not, so "Zenod is great" stays chat. "X is not Y" needs both sides to be roots. |
| Before filing | `engine.chat`, `engine.handleTasking` | The steer check runs before the model and before any capture. A WhatsApp text arrives through Phylax → `chat_with_zenod` → `chat`; MCP `task_brain` arrives through `handleTasking`. So a steer is never filed as a memory. Every reply starts with `Memory tree:` / `Árbol de memoria:` and says in plain words what changed and how to undo it. Spanish and Catalan messages get Spanish replies. |
| Keeper notes | `engine/treeSteer.ts`, `vault/treeSteering.ts` | `alias`, `keep-apart` and `close` join pin and rename. Each is one Keeper note through `steerTree`: the vault write lock, one commit `memory: keeper note K-n (…)`, lint, and a revert on failure. An alias is mirrored onto the root page. `closed` is a new rule. |
| Close honoured | `engine/treeDiscover.ts` | A closed root leaves working memory at the next run and becomes its own long-term area, with its pages. A later pin reopens it, because the later of pin and close wins. |
| "That's wrong" | `git/vaultRepo.ts` (`recentCommits`, `stageRevert`), `engine.undoKeeperChange` | Reverts the newest keeper commit (`memory: keeper…`, `weekly tree sweep…`, `tree…`, `undo…`, `redo…`) with `git revert --no-commit`, as one new commit `memory: undo <sha> (…)`. It runs under the vault write lock, never force-pushes and never touches Log/ or `_attachments/`, and it refuses when the revert doesn't apply cleanly. Saying it again redoes the change (`memory: redo …`); subjects never nest. A bare "that's wrong" counts as an undo only right after a reply that reported a change. Otherwise it is about the last answer. "Undo the last tree change" / "deshaz el último cambio del árbol" works any time. |
| Switch | `EngineOptions.messageSteering` | On by default; `false` turns it off. |

The doctrine is in [LIBRARIAN-DOCTRINE.md](../LIBRARIAN-DOCTRINE.md), "Memory tree", under "Steering by message".
