# E9-3a evidence: retrieval returns tree lineage (2026-11-01)

Parent spine: [EPIC-9 Memory as a tree](../EPIC-9-MEMORY-AS-A-TREE.md) · row E9-3a · run `run_285d73f4-0027-4ef7-a723-51b89b2cf4d2` · PR [#1456](https://github.com/zenod-ai/zenod/pull/1456), stacked on E9-2a [#1453](https://github.com/zenod-ai/zenod/pull/1453)

**Result: done and live.** `search_memory` hits and `get_memory` notes now carry `placement`, `lineage` (level-0 group → level-1 root → … → the memory) and `evidenceRefs` (the page's Log citations). `get_memory` also returns `parent` and `children`. Any page that does not resolve to a lineage gets `placement: unplaced` and `lineage: []`, with no error and no change in ranking. That covers a page with no `parent`, a broken parent, a cycle, Log or receipt files, or an engine without a tree. This page lists paths, counts and SHAs only. It quotes no capture text.
