```
apply on zenod.dev/testers ─► own link ─► sign in (Google/GitHub) ─► 0 euro checkout
   ─► cloud.zenod.dev quick start "Send Zenod a WhatsApp"

   ─► "Message <code> to +34 664 240 219" ─► send it from that phone
```

The "whitelisting" Jordi remembered: the sender check *is* the whitelist. The one number that sends the code is the one number Zenod accepts for that account. No one on our side approves it by hand.

## Snags found

1. **Broken: "Issue new code" and "Show code again" after leaving the page.** Walked 03:48Z on production: the page came back with "Verification is still waiting", I pressed **Issue new code**, and `POST /api/channels/whatsapp/challenge` answered **503** `channels_unavailable` ("Channels are temporarily unavailable. Try again shortly."). **Show code again** did the same. Cause: with the number field hidden, the page sends no number. `zenodPhylax.ts` passes `identity: undefined`, and Phylax's connect tool requires it. The older internal route already fell back to the stored pending number. Anyone whose code expired, or who closed the tab before sending the code, hit this. **Cancel setup** worked (200) and let them start over. Fix: see "Fix" below.
2. **"Verified sender ••••0199 / Verification is not complete yet"** shows while the number is still unverified, and after the 30 minutes run out. The label says "verified" for a number that is not. It is confusing but does not block anyone. Noted, not changed.
3. **The 30-minute expiry is silent.** The page never says the code expires, and a late message gets no reply. With snag 1 fixed, "Issue new code" recovers.
4. **A message from a different phone than the one typed** gets no reply at all.
5. **Reloading the app lands on the home, not Settings** (the settings tab is not in the URL). The quick start card points back to Settings, so it costs one click.
