## The guard ([#1640](https://github.com/zenod-ai/zenod/pull/1640))

`transcribeWithOpenRouter` used to send a note once and trust whatever text came back. Now:

- it probes the mp3 it sends;
- if the answer runs below 50 words per probed minute on 2 minutes or more of audio, it re-runs the note in 10-minute segments and keeps the fuller text. Normal speech is about 130 to 160 words a minute;
- if a segment fails, it keeps the one-shot text;
- every call is metered;
- one log line per note, `transcription.coverage` (audio_seconds, words, words_per_minute, low, segmented), carries numbers only, never text.

WhatsApp notes go through the same code in the Phylax companion, so they get the guard too.

Tests: `packages/server/test/transcribeCoverage.test.ts` covers the maths. `transcribeCoverageSegments.test.ts` runs real ffmpeg against a mocked OpenRouter and covers three cases: an early stop is re-run in 3 segments and joined, a covering answer is not re-run, and a failed segment keeps the one-shot text. Locally the full server suite passed: 183 files, 1841 tests.

PR: [#1640](https://github.com/zenod-ai/zenod/pull/1640). `ci` passed in 10 min 37 s ([run 43062243425](https://github.com/zenod-ai/zenod/actions/runs/43062243425)). It merged into main as **7b2df5a** on 2026-11-11, and the worktree and branch were removed.
