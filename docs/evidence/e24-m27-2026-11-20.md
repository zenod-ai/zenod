- **The build is cleared.** The same 4811f2b build scores rq18 at rank 2 on the old vault and not found on the new one. Production's own c68f23f, the sha that passed yesterday, drops to the same 89.5% on the grown vault. The code change c68f23f..4811f2b (WhatsApp challenge retry, MCP logging, event-loop warning, vault-recovery logging) touches no retrieval.
- **The set's ground truth did not move.** rq18's expected page and the log entry it cites are byte-identical in both vault revisions, so nothing in the question set needed correcting.
- **What the vault change was.** Between `36494d0` and `ae4c296` the vault gained 29 notes, 11 filing records and a log day, and 22 files changed. Two of the new notes and the new day's log now contain the question's key word, and BM25 ranks the two notes above the expected page. That page matches the English question on a single weak word (it is a Spanish voice note), so it sits near the edge of the top 5: its score barely moved (18% to 16%) and its rank fell from 2 to 7. The ranker behaved correctly.
- **Why the gate failed.** 57 questions: one flip is 1.75 points and the floor sat 1.2 points under the passing score. Any growth of the vault could trip it, which made the gate measure the vault and not the build.

## The fix

- `scripts/memory-eval/private-vault.json` pins the vault revision (`36494d0`, where c68f23f passed). `scripts/promote-production.sh` scores the real-note set on that revision and prints `gate: real-note set on vault 36494d0 (pinned ...)`; with no usable pin it falls back to the head; `ZENOD_VAULT_REV=head` scores the head.
- **Not changed:** `floor.json` (90 retrieval), all 57 questions, the demo gate, `nightly.sh` (still scores the live head and appends to `~/zenod-eval/history/private.jsonl`).
- **Moving the pin:** run `run.mjs --dataset private` on the candidate revision and commit the new `rev` only at or above the floor ([docs/memory-test-suite.md](../memory-test-suite.md)).

## Release

`scripts/promote-production.sh` on staging `57104c2` (the merge of #1716): demo 96% ingestion, 100% retrieval, 1.7% errors; real notes 100%, 91.2% (52/57), 1.6%; then `zenod-mt` `c68f23f` to `57104c2`, live after 16 s, promoted 05:14Z. `https://cloud.zenod.dev/api/health` reports `ok`, sha `57104c27f3415dfef7d47b3b789f316e05ef071e`. Rollback: `scripts/promote-production.sh --rollback` (back to `c68f23f`). M23's fix `865b9e8` (#1713) and M25's tenant log line (#1715) are in production.
