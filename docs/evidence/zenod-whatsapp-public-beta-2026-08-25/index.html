The approved product boundary

Zenod is the personal memory agent. It saves text, voice notes, images, and documents; it answers questions from that memory. It does not route to a council, execute code, manage a backlog, or impersonate other agents.

The internal channel service is the phone adapter. The current code name is Phylax. It owns WhatsApp connection, media download, transcription transport, retries, and delivery receipts. It is not a customer product and does not decide what the user meant.

Ring is not deleted. It remains available as a separate multi-agent product, but is not part of the Zenod WhatsApp number.

Failures observed in the last 48 hours

1

Ring invented a success reply

A normal business question received “Done — the change was verified,” unrelated property notes, and an internal test correlation ID.

Remediation

Remove Ring and its reply gate from this number. Send text directly to Zenod. Zenod’s phone persona is memory-only and may only save, retrieve, or clearly say a request is outside the memory product.

2

A retry produced a generic source error

Ring called duplicate memory-search tools, discarded a useful clarification, and returned “I couldn't read the connected source.”

Remediation

One Zenod turn, one memory operation at a time, one customer reply. No Ring tool selection, no duplicate dynamic peer calls, and no internal source language in the WhatsApp response.

3

Two saved memories were reported as failures

Zenod committed both memories, but Phylax’s outer request timed out around 62–64 seconds and told the user the operation failed.

Remediation

Use the existing durable Zenod job ID. Phylax acknowledges the capture, polls to a terminal result, and sends exactly one final receipt. A transport timeout must never overwrite a confirmed Zenod commit.

4

One image classification failed

The classifier returned empty, unparsable structured output. The transaction rolled back cleanly, but the image was not filed.

Remediation

Retry classification a small bounded number of times, then preserve the artifact in Inbox with an explicit “saved, filing pending” receipt. Classification uncertainty must not become data loss.

5

Resending the failed image did nothing

The resend was silently coalesced onto the already-failed canonical job, so it did not create a fresh attempt or reply.

Remediation

Coalesce only while the original job is processing or after it completed. A prior terminal failure must allow a fresh owner/job for a new provider message ID.

6

The audit tool looked in the wrong database

Ring reported no recent WhatsApp rows even though Phylax’s authoritative transcript store contained all ten interactions.

Remediation

Make Phylax the single authority for channel transcripts and expose that evidence directly to Zenod/support tooling. Do not substitute Ring’s empty local channel store.

7

The long voice note was only partly distilled

The raw 27,686-character transcript survived, but speech recognition mangled proper nouns and filing omitted a substantial product/sprint topic.

Remediation

Keep the raw transcript immutable, segment long notes by topic before filing, and retain uncertain named entities verbatim beside normalized candidates.

8

Operational statuses are misleading

A failure message can be successfully delivered while recorded as an outbound error, and the failed classifier call can disappear from a “complete” model timeline.

Remediation

Record operation status and message-delivery status separately. Log failed model calls as first-class attempts so support can reconstruct the exact turn.

What the confusing “typed terminal mutation” sentence means

It is a programming safety rule, not a new product or a Ring concept.

Plain English: when Zenod tries to save something, it must eventually return one machine-readable result tied to that exact message: saved, failed, or still processing. The channel service may say “saved” only when the matching Zenod result says saved. If the user only asked a question, the system must preserve the answer and must not transform it into a fake “change verified” message.

This would have prevented the two worst symptoms: a real save being reported as failed, and a read-only answer being rewritten as an invented success.
