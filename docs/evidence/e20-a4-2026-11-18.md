# E20-A4 evidence: Phylax's nightly CPU on VPS1 (2026-11-18)

Objective: EpicTeam: servers run themselves (and Zenod: 5 testers): Phylax stops loading VPS1 every night.

```
02:00 CET on VPS1 = 19:00 in Mexico City = Jordi's evening voice notes
  voice note ─▶ Phylax ─▶ OpenRouter STT ──402 (key over budget)──▶ local whisper.cpp
                                                         before: 4 threads (all 4 cores), nice 0
                                                         after:  2 threads (half),        nice 19
```

## What runs at 02:00 CET

No cron. Phylax's logs (`docker logs`, container `0ee4233a…`, 18 Nov 00:55-02:50Z) show the gateway's voice-note transcription:

| UTC 18 Nov | event |
|---|---|
| 00:44:51 → 01:05:28 | long note: OpenRouter 402, local whisper.cpp (20.6 min) |
| 01:05:42 → 01:13:26 | note: OpenRouter 402, local (7.7 min) |
| 01:13:37 → 01:17:37 | note: OpenRouter 402, local (4 min) |
| 01:17:57 → 01:49:37 | **923 s note**: OpenRouter 402, local (31.7 min) |
| 01:49:56 → 02:15:48 | **682 s note**: OpenRouter 402, local (25.9 min) |

The same thing happened on 15, 16 and 17 Nov: every note gets `openrouter transcription failed (402) … weight_exceeds_budget`, then `whisper.cpp base`. The nights grow because Jordi's evening notes got longer and more frequent, and every one now runs on the CPU. Phylax's OpenRouter key is provisioned from zenod-mt (`ZENOD_PLATFORM_OPENROUTER_KEY`, a per-app capped key) and is over its cap. No other OpenRouter key was tried. Groq: none on the fleet.

`whisper-cli` ran with `-t 4` (default `ZENOD_WHISPER_THREADS=4`) at normal priority. VPS1 has 4 cores, so each long note took the whole host for up to 32 minutes.

## Fix ([#1693](https://github.com/zenod-ai/zenod/pull/1693))

`packages/server/src/transcribe.ts`: local whisper threads default to half the CPUs (minimum 1, env still overrides), and ffmpeg and whisper-cli run at nice 19 (`ZENOD_WHISPER_NICE`, 0 disables). Notes still get transcribed. They take longer but give way to everything else.

## Timed manual run

The vendored musl binary needs CPU instructions VPS3 lacks, and agents cannot exec into the production container. So the run used whisper.cpp built from the vendored ref `8a9ad78`, the same `base` model and 180 s of audio, pinned to 4 cores (`taskset -c 0-3`) to match VPS1.

| setting | wall | CPU s | avg cores | other CPU work beside it (3.9 s alone) |
|---|---|---|---|---|
| before: `-t 4`, nice 0 | 26.3 s | 98.8 | **3.76** | 7.3 s (1.9× slower) |
| after: `-t 2`, nice 19 | 42.1 s | 83.7 | **1.99** | 3.7 s (not slowed) |
