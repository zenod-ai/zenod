## 1. What was built (`packages/core`, `packages/server`, `apps/web`)

| Piece | Where | What it does |
|---|---|---|
| Stable identity | `engine/treeIdentity.ts` | Each root carries an id, written as an Obsidian block id at the end of its Tree.md line (`^n-1a2b3c4d`, hidden in reading view). A re-derived root inherits the old id it shares at least half its pages with: Jaccard ≥ 0.5, one-to-one, largest overlap first. A new root gets `n-` plus 8 hex of sha1 over its sorted pages. Discovery's heat now goes through the same function. |
| Parity with EpicSpine | `test/fixtures/tree-library-parity.json` | A byte-identical copy of the skill's `assets/tree-library-parity.json` at `af22d92` (E9-5f). All 8 heat cases and all 6 match-id cases pass against Zenod's port. Zenod has no runtime import of the skill. The skill's `recent_changes` cases belong to E9-5c, which writes `## Recent changes`. |
| Keeper notes | `vault/treeSteering.ts` | `## Keeper notes` in Tree.md, one line each: `- K-<n> \| applies to \| rule \| why \| confirmed YYYY-MM-DD`. The rules are `pinned`, `name: X`, `aliases: …`, `keep apart` and `own root`. Notes are only ever appended. A re-derived Tree.md carries them over verbatim, along with `## Recent changes`. Tree lint rejects a malformed note or a repeated id. The E9-5a index reads alias groups from the same notes. |
| Steering in discovery | `engine/treeDiscover.ts` | A pinned root is never demoted and keeps its name and page. A named root keeps the person's name, and no other root may take it. Kept-apart pages and roots never share a topic or area: this is a cannot-link constraint in every merge step, even when the area cap would force a merge. An own root is a topic of its own. Aliases are read as the root's name. Each root's page mirrors its flags (`pinned`, `name-locked`, `aliases`), which are only ever added. A note that names nothing is reported, not acted on. |
| Name stability | `engine/treeDiscover.ts` | A mixed area re-derived as the same parts in another order keeps its previous name. Without this, simulated Sundays on a clone of Jordi's vault flipped "Idealista and Poly-Maker" to "Poly-Maker and Idealista". |
| Memory tab | `POST /api/console/memory-tree/steer`, `engine.steerTree`, `memory-tree-card.tsx` | Pin and Rename on a selected root. The request must be same-origin, and the tenant comes from the session's account only. The engine takes the interactive lane of the vault write queue, the same lock a filing takes. It appends one Keeper note, sets the page flag (for a rename, also the Tree.md line), lints, and makes one commit, `memory: keeper note K-n (…)`. Any failure reverts it. A pinned root shows a "pinned" badge. |

The doctrine is updated in [LIBRARIAN-DOCTRINE.md](../LIBRARIAN-DOCTRINE.md), under "Memory tree".
