## What changed

- **Targets.** `scripts/watchdog/zenod-watchdog.sh` drops the retired hosts (c1, z2, a z-jordi tenant), the dead
  `/api/notify` and `/api/usage/headroom` calls and the old container names. It checks the live page's rows under the
  same keys: `row-1` zenod.dev (200 and a Zenod title), `row-2` cloud `/api/health` "ok", `row-4` Phylax `/api/health`
  "ok" with WhatsApp connected, `row-11` `cloudflared-vps1-sites` active, `row-12` root disk below 90% (warn from 80%).
  It also checks the Docker daemon and swarm crash-loops: 3 or more failed or non-zero-exit tasks of `zenod-mt` or
  Phylax in 15 min. A normal roll is a `shutdown` with exit 0 and is not counted.
- **Sender.** `scripts/watchdog/zenod-alert.sh` writes one atomic queue file to `~t3agent/agent_team_m0/alerts.pending`
  on VPS1. The relay watchdog (agent_team `m0/tools/relay_watchdog.sh`, every minute) sends it to the T3 thread
  "HQ — vps1 alerts" and logs `alert=sent id=<id>` only when T3 accepts it. Dedupe is per key: one alert, a re-alert
  every 30 min while it stays red, and one `[RECOVERED]` with the red-since time. Messages are one line, at most 600
  characters, and hold names, codes and timestamps only. Zenod's WhatsApp is not used (root L-6). Zenod is not
  touched (L-7).
- **Live page.** After each 5-min run, `docs/health/s1-live/probe.py` sends every component except the watchdog row
  through `zenod-alert.sh rows`. A red component goes out as `row-<n>` and anything else clears it. One outage seen by
  both the page and the watchdog therefore alerts once. S2 can call the same command or source the library. In the
  aggregator (`aggregate.py`), the watchdog row reads the new user timer, the sender log and the relay's receipts. It
  is red if the timer is not active, if no run happened in 10 min, or if any queued id was not sent within 10 min.
- **No root.** VPS1 root is Jordi's only (infra-vps AGENTS.md, L-F5), so the watchdog now runs as the t3agent **user**
  timer `zenod-health-watchdog.timer` (linger is on). It uses only the existing read-only sudo rules for swarm tasks.
  It is installed in `~/.local/share/zenod-watchdog/` because `~/.local/lib` on VPS1 is root-owned.
- **Tier 2: not added.** The only Telegram bot is Phylax's, which is Zenod's (`secret find telegram` →
  `TELEGRAM_BOT_TOKEN`, app `phylax`). No chat is bound for Jordi, and no ntfy or pushover key exists. One tier
  remains. If VPS1 itself is down, the HQ queue is down with it, and the page shows its red "stale" banner after
  15 min.

## Left open

- The retired root unit `zenod-watchdog.timer` still runs every 2 min. It checks the dead hosts and logs
  `delivery=no`, and it is harmless otherwise. The page notes it on the watchdog row. Switching it off is a root step
  on VPS1: `sudo systemctl disable --now zenod-watchdog.timer`, then optionally `sudo rm -r /opt/zenod-watchdog
  /etc/zenod-watchdog.env`. Rollback is `sudo systemctl enable --now zenod-watchdog.timer`.
