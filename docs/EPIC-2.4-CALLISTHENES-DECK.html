The outbound identity broker.

Callisthenes is the always-on MCP unit that holds outbound credentials once, then lets Claude, Cursor, the Ring, scripts, and future agents send through one guarded endpoint.

Product promise

Authorize each platform once. Every agent can use the outbound identity without holding the platform secret.

Evidence promise

A mutating tool returns a concrete ID or URL, or fails loudly. No assistant can claim a send without a receipt.

Guardrail promise

Every send is blocked until explicitly approved, then counted against a conservative hourly throttle.

Packaging promise

Hosted gets checkout, one connect screen, metering, and watchdog. Self-host gets the same unit as Docker compose.

What becomes possible

A user can delegate outbound posting to any agent without copying platform credentials into every agent environment.

What stays impossible

An unapproved draft, over-throttle send, revoked connection, or missing connector returns an explicit error instead of quietly sending.

Self-Hosted

Self-hosted is the same sender, without the hosted funnel.

Self-host users bring their own X app credentials, run Docker compose, and point their MCP client at the local HTTP endpoint. The connect page is not the product surface here.

Docker compose localhost:8000/mcp same guardrails

Runs

One `callisthenes` container exposing Streamable HTTP on port 8000, with read and write tools on one endpoint.

Requires

X app values in `.env`: consumer key, consumer secret, bearer token, access token, access token secret.

Protects

`createPosts`, `deletePosts`, `mediaUpload`, and `post_reddit` are guarded by approval and throttle middleware.

Returns

Concrete tool receipts: IDs, permalinks, or explicit errors. No hidden dashboard state is needed.

Hosted vs Self-Hosted

Different onboarding, same outbound contract.

Hosted Callisthenes

Who runs itZenod infrastructure via Dokploy, per paid user.
How auth worksOne connect screen: X OAuth2 PKCE callback plus Reddit token row.
What user copiesMCP URL and access token after checkout/provisioning.
Ops includedStripe provisioning, usage ledger, watchdog registration, restore path.
Best forPeople who want outbound identity without running servers or handling X app secrets.

Self-Hosted Callisthenes

Who runs itThe user, from `units/callisthenes/docker-compose.callisthenes.yml`.
How auth worksOwner-provided X app credentials in `.env`; hosted UI is optional plumbing, not the main path.
What user copiesLocal MCP endpoint, usually `http://localhost:8000/mcp`.
Ops includedContainer restart policy and local logs; no Stripe, provisioner, or fleet watchdog.
Best forDogfood, developers, and users who already own the platform app credentials.
