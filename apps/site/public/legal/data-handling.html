Data Handling

Effective 13 August 2026 · Version 2026-08-13. This page explains, in plain terms, where your data lives and who touches it in hosted Zenod. It complements the Privacy Policy.

The design principle behind hosted Zenod: the customer owns the vault repo. Your knowledge is not locked inside our database — it is a Git repository you can clone, read, and take with you at any time. This page maps each kind of data to where it lives and how it is isolated.

The tenant boundary

Hosted Zenod is a multi-tenant service. Each request is authenticated to a tenant; tokens are stored as hashes, tenant state is rooted under a separate storage prefix, credentials are encrypted with tenant-bound associated data, and suspended tenants cannot use MCP. Automated isolation tests exercise cross-tenant token, session, settings, and storage boundaries.

Backups

Your vault is committed and pushed to its Git repository when a write journey completes. Hosted runtime state is also covered by checksummed, access-restricted cold volume backups. Public paid signup fails closed unless an operator has recorded a successful isolated restore verification within the preceding 31 days.

Export and deletion

Export: clone your vault repo any time. On a verified account deletion request we revoke the tenant's MCP tokens and connected credentials and remove tenant runtime data according to the Privacy Policy. Deleting hosted data does not delete a repository in your GitHub account.

Who processes your data

See the sub-processor list in the Privacy Policy (model providers, Stripe for payments, our hosting provider). Each touches only the slice needed to run its part.
