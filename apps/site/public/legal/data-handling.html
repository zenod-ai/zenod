The design principle behind hosted Zenod: the customer owns the vault repo. Your knowledge is not locked inside our database — it is a Git repository you can clone, read, and take with you at any time. This page maps each kind of data to where it lives and how it is isolated.

The container-per-tenant boundary

Every customer gets a dedicated, single-tenant stack on a private per-tenant network. The network is the tenant boundary: your agents can reach each other but cannot see any other customer's containers or credentials. You run the exact same open-source image we publish and dogfood — no special hosted fork of the product.

Backups

Your vault's backup is built in: it is a Git repository, pushed continuously, so its history is your backup. For tenant runtime state (sqlite), we add volume snapshots as part of hosted operations.

Export and deletion

Export: clone your vault repo any time — nothing to request. On account deletion we transfer any platform-held vault to you and destroy your container volume (including credentials and usage ledger).

Who processes your data

See the sub-processor list in the Privacy Policy (model providers, Stripe for payments, our hosting provider). Each touches only the slice needed to run its part.
