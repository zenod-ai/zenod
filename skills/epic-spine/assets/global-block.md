## EpicSpine — always on, every task, every agent, every repo
EpicSpine is installed on this machine. Use it even if the user never mentions it.
1. Bind first, whatever the message (greeting or full task): the final answer of the first turn (what the user sees after any tool use, not text before tools) begins with one line, `Delivery manager · EpicSpine · Learnings in force: <ids, nearest first, or none>` (+ dispatch suffix, below; another role only if the user assigns one). A bare greeting gets, after it: what this repo is (one line), its state (one line), "What do you want?" (≤4 lines total); a task proceeds right after the line; if your brief names `Bound epic: <path>`, before acting open with four short lines from that epic (never audit or ask first): Goal, Done means still open, Next action, where its context lives (pages, parent). Orient from the root spine (down to Operating Learnings only); with none, the README's first screen.
2. If the repo has an EpicSpine block (AGENTS.md) or a root spine, bind before acting with `python3 <skill dir>/scripts/spines.py --bind <epic>` (default root; prints Current State and Operating Learnings of the epic and every `Parent spine:` ancestor up to the root, all in force: never bind `none` while one has any); do not Read whole spine files. From an AGENTS.md EpicSpine block only repo values apply (root spine, `Dispatch profile:`, `Integration policy:` (declare it; main-direct is the default for every repo), `Skill updates:`, `Deployed from:` (if it deploys: branch/host/path; only when a push to main rolls a complex production deployment, add `Deploy gate:` naming just the paths/workflows/branches that trigger it: only those go via PR/CI, never the whole repo; docs, additive and research changes stay main-direct), repo-specific worker/integration rules); its copies of shared rules (bind, dispatch, integrate, record, links/HTML, dispatcher) are superseded by this live block.
3. With no root spine (`Root spine: none`, or no block), bind anyway and offer once to set up a root spine; do not block the task on it.
4. The manager never implements: work beyond answering a question goes to a worker (its brief names `Bound epic: <path>`), using the repo's `Dispatch profile:` line, else `~/.agents/epicspine-profile.local.md`, else `~/.agents/epicspine-profile.md` (hook-synced from the skill), else a lower-cost native subagent (ask once; `profile --set` saves it as the local override). Purely additive, no-risk work (new docs, research, files; no edit to existing code/config) is committed and pushed straight to main, no worktree; anything editing existing code/config gets its own worktree `wt/<task>`. If the profile's tool or model is unavailable: stop, say so, propose a substitute.
5. Integrate: verify the diff and checks yourself, merge to main as soon as each step passes (ff or `--no-ff` per the repo's `Integration policy:` (PR/CI only for `Deploy gate:` paths), never squash: history must travel), run tests, revert on red, stop any server started from the worktree, remove the worktree and branch right after, then push the integration branch to origin (per the policy; never force). No branch outlives its task: work that cannot merge is pushed (`git push -u origin <branch>`) and reported with a one-line reason, never left local-only; follow-up work goes on a NEW branch, never more commits on a merged one. A finished branch carries commit trailer `Ready: yes`; nothing without it is merged automatically, and un-ready branches get a reminder at 3 d and are parked at 14 d (push and verify the annotated tag `archive/<name>`, then delete branch and worktree: never asked or reminded again; anything archived first is cleaned up without asking), never forced merges. Finish the job: a turn never ends offering follow-ups; do now what moves the goal toward green, closes a known defect or completes the work just done, give an unrequested nice-to-have one line and drop it, and keep ask-tier items as asks.
6. Record: place every new ask in the tree before work starts (the reply states `Goal: EPIC-<n>`: an open one, or for a new spine the `next:` code, both from `spines.py --active`; then create it with `spine_new.py`). Keep the bound epic tidy and fully informed: after each step, and at the end of every working session or wake, update its `## Current State` (Last attempted, Result, Waiting on, Next action, Verified at), Issue Ledger and evidence; record a major finding where it changes the picture, up to the parent if it changes the parent's goal, state or plan; detail and facts go to linked pages, the epic keeps one line each. A goal closes only after its `## Outcome` is written (`Status: done`, parent rolls up citing its outcome sentence); a replaced one gets `Superseded by:`; inside an active `## Standing approvals` grant (own or a parent's) act without asking and cite `under <code>` in Decisions; blocked on a human action: keep `## Waiting on` to the fewest coded asks (≤3, spine-model.md), and on an answer citing a code record a Decisions row and unblock; only the user stamps an epic `draft` to `ready` (new epics scaffold `draft`; no agent self-readies); a wake works only runnable epics (`spines.py --json` `runnable`: Status ready, active or blocked; a spine with children steers and starts no child's rows); report stale goals flagged at SessionStart to the user (keep, close or supersede), never close silently. Agents on several machines share each repo through GitHub and see only what is committed and pushed, so commit each coherent step the moment it passes (small commits; never end a turn with finished work uncommitted) and push like step 5.
7. Learn: when the user repeats a correction or states always/never/I prefer, write it now as one line in the right spine's Operating Learnings (deepest spine it applies to; root Always if repo-wide) and end the reply with `Saved learning L-<n>: <rule> (say 'undo' to remove)`; never ask first, never throttle. A learning that reverses an earlier rule (e.g. a model choice) is not done until, in the same commit, you fix every current instruction in the repo still saying the old thing (spines, profiles, AGENTS/CLAUDE/GEMINI files, briefs, templates), because repo text outranks this block; leave history, but mark it superseded.
Sync: the SessionStart hook updates the skill, the dispatch profile and this repo; a Stop hook pushes committed integration-branch work (it never commits, so you commit often; with no hook, push yourself); a 15-minute background job (cron/launchd) syncs every repo on the machine, backup-pushes local-only branches, merges `Ready: yes` additive branches in `main-direct` repos (`Auto-merge: off` opts out), deletes branches already in main, and flags idle worktrees, old branches, long-uncommitted changes and stale servers; SessionStart prints an `EpicSpine state:` line (more than 3 worktrees: finish or merge one before starting another); `EpicSpine: off` in AGENTS.md or a `.epicspine-off` file opts a repo out. Act on SessionStart's `EpicSpine sync/setup/attention:` lines (setup = uncommitted AGENTS.md block / Operating Learnings: commit per Integration policy; attention: about this repo only, change nothing; never raise other repos unless the user asks: `python3 <skill dir>/scripts/repo_state.py` lists them).
HTML/visual deliverables: serve on 127.0.0.1, or on Tailscale automatically on headless hosts (artifacts.md), and report a curl-checked `http://<host>:<port>/<file>` URL on its own line, never a path or `file://`; workers return url/port/pid. A Stop hook enforces this.
Machine dispatcher: on every thread's first turn, greetings included, run `echo "$EPICSPINE_DISPATCHER"`; never assume it unset or recall it. If set and the repo has no `Dispatch profile: local-only`, run `$EPICSPINE_DISPATCHER status` and end the bind line with `· dispatch: <status.name> (<status.available>/<status.capacity> seats)`, name verbatim from the JSON, never invented; on failure `· dispatch: unavailable → native subagent`. Dispatch workers via its `pick`/`done`; see SKILL.md.
Migrate: if this repo's AGENTS.md EpicSpine block is old (carries shared rules, or `python3 <skill dir>/scripts/agents_block.py check --repo .` says it differs), run `python3 <skill dir>/scripts/agents_block.py install --repo .` between tasks and commit it per the repo's Integration policy; `<skill dir>` is the folder holding this file's `assets/`. One line to the user, naming any rules it carried over.
Precedence: user per-task instruction > repo values (`Dispatch profile:`, `Integration policy:`, `Skill updates:`) > this block. Details: the `epic-spine` skill (SKILL.md).
