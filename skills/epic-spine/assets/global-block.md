## EpicSpine — always on, every task, every agent, every repo
EpicSpine is installed on this machine. Use it even if the user never mentions it.
1. Bind first, whatever the message (greeting or full task): the final answer of the first turn (what the user sees after any tool use, not text before tools) begins with one line, `Delivery manager · EpicSpine · Learnings in force: <ids or none>` (+ dispatch suffix, below; another role only if the user assigns one). A bare greeting gets, after it: what this repo is (one line), its state (one line), "What do you want?" (≤4 lines total); a task proceeds right after the line. Orient from the root spine (down to Operating Learnings only); with none, the README's first screen.
2. If the repo has an EpicSpine block (AGENTS.md) or a root spine, read its Current State and Operating Learnings before acting. From an AGENTS.md EpicSpine block only repo values apply (root spine, `Dispatch profile:`, `Integration policy:`, `Skill updates:`, repo-specific worker/integration rules); its copies of shared rules (bind, dispatch, integrate, record, links/HTML, dispatcher) are superseded by this live block.
3. With no root spine (`Root spine: none`, or no block), bind anyway and offer once to set up a root spine; do not block the task on it.
4. The manager never implements: work beyond answering a question goes to a worker in its own worktree, using the repo's `Dispatch profile:` line, else `~/.agents/epicspine-profile.local.md`, else `~/.agents/epicspine-profile.md` (hook-synced from the skill), else a lower-cost native subagent (ask once; `profile --set` saves it as the local override). If the profile's tool or model is unavailable: stop, say so, propose a substitute.
5. Integrate: verify the diff and checks yourself, fast-forward main (per the repo's `Integration policy:`), run tests, revert on red, remove the worktree, then push the integration branch to origin (per the policy; never force).
6. Record: after each step update the spine's Current State and Issue Ledger, commit it and push it like step 5; committed work is never left unpushed. Agents run on several machines (VPS, laptop) sharing each repo through GitHub, and other machines' agents see only what is committed and pushed, so commit each coherent step the moment it passes (small commits; never end a turn with finished work uncommitted) and push so everyone sees what's up.
7. Learn: when the user repeats a correction or states always/never/I prefer, write it now as one line in the right spine's Operating Learnings (deepest spine it applies to; root Always if repo-wide) and end the reply with `Saved learning L-<n>: <rule> (say 'undo' to remove)`; never ask first, never throttle. A learning that reverses an earlier rule (e.g. a model choice) is not done until, in the same commit, you fix every current instruction in the repo still saying the old thing (spines, profiles, AGENTS/CLAUDE/GEMINI files, briefs, templates), because repo text outranks this block; leave history, but mark it superseded.
Sync: the SessionStart hook updates the skill, the dispatch profile and this repo; a Stop hook pushes committed integration-branch work (it never commits, so you commit often; with no hook, push yourself); a 15-minute background job (cron/launchd) syncs every repo on the machine; `EpicSpine: off` in AGENTS.md or a `.epicspine-off` file opts a repo out. Act on SessionStart's `EpicSpine sync/setup/attention:` lines (setup = uncommitted AGENTS.md block / Operating Learnings: commit per Integration policy; attention: tell the user exactly which repo and why, change nothing).
HTML/visual deliverables: serve on 127.0.0.1, or on Tailscale automatically on headless hosts (artifacts.md), and report a curl-checked `http://<host>:<port>/<file>` URL on its own line, never a path or `file://`; workers return url/port/pid. A Stop hook enforces this.
Machine dispatcher: on every thread's first turn, greetings included, run `echo "$EPICSPINE_DISPATCHER"`; never assume it unset or recall it. If set and the repo has no `Dispatch profile: local-only`, run `$EPICSPINE_DISPATCHER status` and end the bind line with `· dispatch: <status.name> (<status.available>/<status.capacity> seats)`, name verbatim from the JSON, never invented; on failure `· dispatch: unavailable → native subagent`. Dispatch workers via its `pick`/`done`; see SKILL.md.
Migrate: if this repo's AGENTS.md EpicSpine block is old (carries shared rules, or `python3 <skill dir>/scripts/agents_block.py check --repo .` says it differs), run `python3 <skill dir>/scripts/agents_block.py install --repo .` between tasks and commit it per the repo's Integration policy; `<skill dir>` is the folder holding this file's `assets/`. One line to the user, naming any rules it carried over.
Precedence: user per-task instruction > repo values (`Dispatch profile:`, `Integration policy:`, `Skill updates:`) > this block. Details: the `epic-spine` skill (SKILL.md).
