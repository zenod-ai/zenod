# Session self-sync

Why: the user's agents run on several machines (a VPS, a laptop) that share each repo only through GitHub, so uncommitted or unpushed work is invisible to the other machines' agents and makes clones diverge. Agents commit each coherent step as soon as it passes and push it (the Stop hook does the push; it never commits); session start pulls.

`scripts/session_sync.py` runs from the SessionStart hook, so no agent has to remember to upgrade (`EPICSPINE_SYNC=off` disables it; one 10 s deadline, short per-call timeouts, never raises, never forces):

- **Skill**, at most once per 10 minutes (stamp `~/.agents/epicspine-sync.stamp`): a source checkout (skill dir is `<repo>/skill/epic-spine`) is fetched and fast-forwarded when its tree is clean and only behind; a pinned or unpinned installed copy uses `skill_update.py`'s verified upgrade when `ls-remote` shows a new commit. Vendored copies are left to `SYNC.md`; a repo `Skill updates: off|manual` skips it. Context line: `EpicSpine sync: skill 2026.10.16.3 -> 2026.10.16.4`.
- **Profile**: `~/.agents/epicspine-profile.md` is rewritten from `assets/epicspine-profile.md` unless `~/.agents/epicspine-profile.local.md` exists (`agents_block.py profile --set` writes that override).
- **Repo** (`scripts/repo_sync.py`): fetch; clean + only behind -> fast-forward; ahead on the integration branch -> push fast-forward-only (not under `Integration policy: pr-approval`); diverged, or behind with a dirty tree, on the integration branch -> nothing changes and an `EpicSpine attention:` line names the repo and why.
- **Repo setup**, every git repo with an origin, spine or not: no current AGENTS.md block -> `agents_block.py install`, with `Root spine: none` when no root spine is discoverable (an `EPIC.md` without `## Current State` is not one), and a root spine lacking `## Operating Learnings` gets an empty section. Left uncommitted, one `EpicSpine setup:` line asks the agent to commit. Several candidate spines: the block says `none` and an `EpicSpine attention:` line asks the user which is root (then `install --root-spine <path>`). Linked worktrees are left to the primary checkout; a `none` block upgrades itself once a spine appears.
- **Vendored skill copies**, same throttle as the skill step: a directory in the current repo (depth <= 4; not `.git`, `node_modules`, `wt`/worktrees) holding a `SKILL.md` named `epic-spine` and a `VERSION` whose date (`YYYY.MM.DD` prefix) is more than 7 days older than the installed skill's gets one line (a copy a few releases behind, e.g. a pinned `.9` against `.10`, is tolerated), `EpicSpine attention: <repo>: old copy of the epic-spine skill at <relpath> (<v>, installed <v>); agents reading it get stale rules — update or remove it`. Report only; nothing is changed. A repo can shadow the live skill with a copy and so with old rules (zenod kept DeepSeek names that way).
- **Hook re-registration** (`scripts/rehook.py`): the skill update only swaps code, so after every update, and whenever a hook is missing (local check, no network; at most once per 10 minutes per harness), the hook re-runs `agents_block.py install-global --only <harness>` as a subprocess of the on-disk script: Claude Code in `CLAUDE_CONFIG_DIR` or `~/.claude`, Codex in `CODEX_HOME` or `~/.codex` when `codex` is on PATH. Only config dirs that already carry EpicSpine; a hook registered from another checkout is not repointed; Claude 6 s / Codex 9 s caps (Codex trust lookup 5 s: slower means hooks registered, untrusted). Context line when something changed: `EpicSpine sync: skill 2026.10.16.5 -> 2026.10.16.6; hooks re-registered (Stop push added)`. No manual re-run of `install-global` after the first install.
- **Background sync** (`scripts/background_sync.py`, scheduled by `scripts/sync_schedule.py`): SessionStart only touches the repo an agent opens, so repos nobody opened lag behind origin, never get the per-clone pre-commit gate (`.git/hooks` is not in git) and their warnings go unseen. A machine-wide job every 15 minutes closes that on every machine. Roots: `EPICSPINE_REPO_ROOTS` (`os.pathsep` list) else the existing ones of `~/github`, `~/Documents/GitHub`, `~/code`, `~/src`; main checkouts at depth <= 2 (linked worktrees and submodules have a `.git` file: skipped) with an `origin` and a commit on any ref in the last 90 days; `.epicspine-off` / `EpicSpine: off` repos skipped. Per repo it reuses the SessionStart logic: fetch, ff-only when clean and behind, push committed integration-branch work per Integration policy (never forced, never committed, dirty files untouched), the pre-commit gate where an AGENTS block or spine exists (a foreign hook is never replaced) and the vendored-copy check. It never installs AGENTS.md blocks (that would leave uncommitted files in unattended repos). Bounds: 20 s per repo, 5 min total (least recently synced first, so none starves), `GIT_TERMINAL_PROMPT=0` and ssh BatchMode, a `~/.agents/epicspine-sync.lock` flock against overlap, silent unless `-v`. It writes `~/.agents/epicspine-sync-status.json` (per repo: `last_run`, `branch`, `ahead`/`behind`, `pulled`/`pushed`, `attention` reasons). **SessionStart** reads it and prints `EpicSpine attention: <why> (background sync; change nothing)` for the current repo only (its local mess and stale goals; its sync `attention` is the live check's; at most 5), and one line when the job has not run for 24 h. Other repos are recorded, never shown in a session (root L-18); `python3 scripts/repo_state.py` prints the table on request. **Scheduling**: `install-global` (and `rehook.py` after every self-update, or when the entry is missing: throttled, local check) installs it, `uninstall-global` removes it, `check-global` reports it (exit 1 when missing). Linux: one user-crontab line tagged `# epicspine-background-sync`, other entries preserved, an unreadable crontab never overwritten; macOS: `~/Library/LaunchAgents/dev.epicspine.sync.plist` (`StartInterval 900`, `RunAtLoad`) loaded with `launchctl bootstrap gui/$UID` (fallback `load -w`). `--home` overrides never touch crontab or launchd. `EPICSPINE_SYNC=off` disables the job and its install. Needs git credentials that work unattended (ssh key without prompt or agent, credential helper); a repo that cannot fetch just stays as it was.
- **Fetch guard** (`scripts/fetch_guard.py`, used by `repo_sync.sync` and `auto_return.py`): a fetch that times out kills git's whole process group and deletes only the `tmp_pack_*`/`tmp_idx_*` files that run created (a killed fetch restarts from zero and used to leave one per run: 17 GB, a full disk). Two timeouts in a row back that repo off (30 min, doubling, max 6 h; state in `<git-dir>/epicspine-backoff.json`) with an `EpicSpine attention:` line naming the repo path for a manual `git fetch origin`; a successful fetch resets it.
- **Local mess** (`scripts/local_mess.py`, `scripts/local_servers.py`; called per repo by the background job, 40 s extra; pushes, `auto_return.py` and `repo_state.py` below are the only writers): work that exists on one machine is invisible to the others. (1) **Backup push**: each local branch except the integration branch with commits on no origin branch gets `git push [-u] origin refs/heads/b:refs/heads/b` (upstream only when none; never forced, <= 10 per run, 10 s each, also under `pr-approval`). Diverged from `origin/b`, or the push rejected: an attention line (`<repo>: branch b has n commit(s) only on this machine and ... — merge or rebase it ..., never force`), no retry with force. Off: `EPICSPINE_PUSH_BRANCHES=off`, or `Push branches: off` in the repo's AGENTS.md. (2) **Report** (status file key `mess`, shown at SessionStart only in a session inside that repo; <= 3 lines per kind per repo, then `N more`): linked worktrees idle > 3 days (newest of last commit, dir and dirty-file mtime) and not merged into `origin/<integration>` (`<repo>: worktree <path> (<branch>) idle <n>d, not merged — merge it or remove it`); merged, clean, idle > 1 day (`... already merged — safe to remove (git worktree remove <path>)`); tracked changes in the main checkout for > 24 h by oldest changed-file mtime or first seen dirty by an earlier run, so a cron-rewritten file still counts (`<repo>: uncommitted changes for <n>h in <files> — commit them or discard`); server-like processes (`http.server`, `serve`, `http-server`, ...) running > 24 h with cwd or `--directory` inside a linked worktree (`<repo>: http server pid <pid> serving <path> for <n>d — stop it when done`; `/proc` on Linux, `ps` + `lsof -d cwd` best effort on macOS). (3) **Return to main** (`scripts/auto_return.py`; needs network, skipped when the repo's fetch just timed out): fetches with `--prune`; in a repo with an explicit `Integration policy: main-direct` (not opted out by `EPICSPINE_AUTOMERGE=off` or `Auto-merge: off` in AGENTS.md) a local or origin branch whose tip commit has the trailer `Ready: yes` is merged when its diff against the merge-base only adds files (no M/D/R/T, nothing under `.github/` or named `.git*`) and touches no `Deploy gate:` entry (path prefix or glob, read from AGENTS.md and the root spine by `scripts/deploy_gate.py`; reported `touches Deploy gate <entry>`; a gate value that is not only paths/globs, e.g. a branch name or prose, or an `Integration policy:` text mentioning a PR or CI such as zenod's, blocks the whole repo and says why: when in doubt, no merge), `git merge-tree --write-tree origin/<integration> <tip>` is clean, `gh pr list --head <b> --state open` runs and is empty (no `gh` or an error: no merge), the tip is >= 2 h old and its worktree, if any, is clean with no process inside (`/proc` cwd, `lsof` on macOS): `--no-ff` merge in a temporary detached worktree, push ff-only (rejected: stop and report; the next run retries), then the worktree (never forced), the local branch and the origin branch (tip re-verified with `ls-remote`) are removed; <= 3 merges per run; fast-forwards the primary checkout when it sits clean on the integration branch. A branch already in `origin/<integration>` with no worktree is deleted locally (kept when its tip IS the integration tip: it may be brand new); on origin only `wt/*`, any other is one `N branch(es) already in main — safe to delete` line. Reported only, one line per kind per repo (status `mess`): Ready but not auto-merged (with the reason), unmerged idle >= 3 d, idle >= 14 d (`park it: ...archive/<name>...`; worktrees get the same wording; a branch or worktree tip already under an `archive/*` tag is never reported), skipped under `pr-approval`. Merged actions go to the status file key `auto`. (4) **State and cap** (`scripts/repo_state.py`): status key `state` (`dirty`, `ahead`, `behind`, `worktrees`, `unmerged`); SessionStart prints for the current repo `EpicSpine state: <repo> main clean|dirty(N), in sync|ahead N|behind N · worktrees N · branches not in main N` (local refs only) and, above 3 linked worktrees, `EpicSpine attention: <repo>: N open worktrees (cap 3) — finish or merge one before starting another`; `python3 scripts/repo_state.py [--home DIR]` prints a table of every repo from the status file (repo | main state | ahead/behind | worktrees | not in main | attention). It never commits, forces, touches dirty files or kills a process; squash-merged branches look unmerged. Rules for agents: `references/hygiene.md`.
- **Opt-out**: a `.epicspine-off` file or an `EpicSpine: off` line in AGENTS.md skips repo sync, setup and the Stop push entirely. Repo pull/push never needs a spine.
- **Stop hook** (`scripts/stop_push.py`, Claude Code and Codex): at the end of every turn, in the current repo, push the integration branch when it is checked out, ahead of its local `origin/<branch>` ref and not behind, the tracked tree is clean (untracked is fine) and the policy is not `pr-approval`. Fast-forward only, never forced, never commits, prints nothing, always lets the turn end, 8 s cap; the same HEAD is not retried within 60 s (stamp `~/.agents/epicspine-push/`). Diverged or rejected: silent, the next SessionStart reports it. Worker branches are not pushed.

New machine, one line: `git clone https://github.com/AlfaBlok/epicspine-skill ~/github/epicspine-skill && python3 ~/github/epicspine-skill/skill/epic-spine/scripts/agents_block.py install-global`.

## Codex

Codex CLI 0.131 supports hooks (`codex features list`: `hooks stable true`; `$CODEX_HOME/hooks.json`, same schema as Claude Code; SessionStart `additionalContext` is injected as developer context). A user hook only runs once trusted (`[hooks.state."<hooks.json>:<event>:<i>:<j>"] trusted_hash` in `config.toml`; otherwise "needs review" in `/hooks`). `install-global` therefore writes SessionStart (`print-hook`, sync side effects) and Stop (`stop_push.py`) into `~/.codex/hooks.json`, asks the local `codex app-server` (`hooks/list`, offline) for each hook's hash and writes those entries in one managed block of `config.toml` (`scripts/codex_hooks.py`); uninstall removes both. Without a `codex` binary the hooks stay unreviewed, so the `~/.codex/AGENTS.md` pointer also says: if the block was not injected, run `agents_block.py print-hook` first. Limits: the `url_gate` Stop hook is Claude-only; after Codex changes a hook definition or hash format, the next missing/updated sync re-runs `install-global --only codex`, or run it by hand.
